# ThemeProvider

Resolves the light, dark or system theme and writes it onto the document for every component to
read. Almost nothing in this kit has a colour of its own. Components read custom properties this
provider's classes define, so a page without it renders with them unset.

## Use this when / not when

- Mount it once, at the root of an application of your own, around everything that uses the kit.
- Not inside an ONLYOFFICE Apps plugin. The portal has already mounted it, and a second one would
  write the same attributes twice.
- Not [`ThemeProviderComponent`](../../components/theme-provider/README.md) directly. It is the
  layer below, and its theme object can easily disagree with itself.
- Not `Providers` from `@onlyoffice/apps-ui-kit/providers/Providers`. It also mounts an API client
  and needs a portal URL and an API key.

## Import

```ts
import { ThemeProvider } from "@onlyoffice/apps-ui-kit/providers/theme";
```

Also exported from the root barrel `@onlyoffice/apps-ui-kit`.

Needs no provider of its own. Pair it with
[`TranslationProvider`](../translation/README.md), which the components that carry labels of
their own read.

## Minimal example

```tsx
import { ThemeProvider } from "@onlyoffice/apps-ui-kit/providers/theme";
import { ThemeKeys } from "@onlyoffice/apps-ui-kit/enums";
import { Button } from "@onlyoffice/apps-ui-kit/components/button";

export function App() {
  return (
    <ThemeProvider initialTheme={ThemeKeys.BaseStr} locale="en">
      <Button primary label="Save" onClick={() => {}} />
    </ThemeProvider>
  );
}
```

## Recipes

### Follow the operating system

`ThemeKeys.SystemStr` reads the system's preference and keeps reading it. A theme switched in the
operating system switches here without a reload.

```tsx
import { ThemeProvider } from "@onlyoffice/apps-ui-kit/providers/theme";
import { ThemeKeys } from "@onlyoffice/apps-ui-kit/enums";

export function SystemThemed({ children }: { children: React.ReactNode }) {
  return (
    <ThemeProvider initialTheme={ThemeKeys.SystemStr} locale="en">
      {children}
    </ThemeProvider>
  );
}
```

### Let the reader choose

The choice lives in your own state and reaches the provider as `initialTheme`. A new value is
applied in place. Nothing below the provider remounts, so a form keeps what the reader has typed.

```tsx
import { useState } from "react";

import { ThemeProvider } from "@onlyoffice/apps-ui-kit/providers/theme";
import { ThemeKeys } from "@onlyoffice/apps-ui-kit/enums";
import { Button } from "@onlyoffice/apps-ui-kit/components/button";

export function ThemeSwitch() {
  const [theme, setTheme] = useState(ThemeKeys.BaseStr);

  return (
    <ThemeProvider initialTheme={theme} locale="en">
      <Button
        label="Switch"
        onClick={() =>
          setTheme(
            theme === ThemeKeys.BaseStr ? ThemeKeys.DarkStr : ThemeKeys.BaseStr,
          )
        }
      />
    </ThemeProvider>
  );
}
```

### Right to left

`locale` decides the direction, from a list of twelve right-to-left languages matched by the part
before the hyphen. Nothing else has to be set: the `rtl` class and `data-dir` go on the document.

```tsx
import { ThemeProvider } from "@onlyoffice/apps-ui-kit/providers/theme";
import { ThemeKeys } from "@onlyoffice/apps-ui-kit/enums";

export function Arabic({ children }: { children: React.ReactNode }) {
  return (
    <ThemeProvider initialTheme={ThemeKeys.BaseStr} locale="ar">
      {children}
    </ThemeProvider>
  );
}
```

## Behaviour the types don't state

- **It writes on the document as well as into React context.** `light` or `dark` and `ltr` or
  `rtl` go on `<body>`, `data-theme` and `data-dir` on `<html>`. The provider mounted last wins,
  and an unmounted one hands the page back.
- **`initialTheme` keeps being read.** An effect re-resolves the theme when it changes, so a new
  value applies in place with no state lost below the provider.
- **The system theme keeps being followed.** A `prefers-color-scheme` listener stays attached while
  the provider is mounted. It changes the theme under `ThemeKeys.SystemStr`, or with
  `initialTheme` and `systemTheme` both left out.
- **`systemTheme` counts only when `initialTheme` is left out.** Under `ThemeKeys.SystemStr` the
  real preference is read and `systemTheme` is ignored.
- **Each resolve writes a `system_theme` cookie** holding the system's preference.
- **`colorTheme` is the only way to the portal's accent palette.** Nothing is fetched; without the
  prop the kit's own accent stays. Its `selected` id picks one entry of its `themes`.
- **A `colorTheme` that arrives later is picked up.** A portal that loads its palette after the
  first render can pass it in without remounting the provider.
- **The font is not shipped.** The family is `Open Sans, sans-serif, Arial`; load Open Sans
  yourself. Arabic, `ar` in any region, gets the system's font stack instead.

## Accessibility

- The provider renders no element of its own. Its props accept no `aria-*`, and there is no
  element to put one on.
- The `light` and `dark` classes give every component its contrast. On a page without this
  provider, text can land on a background it was never checked against.
- `locale` sets the writing direction for the whole document. Set it to the language you are
  actually rendering, or a right-to-left interface reads left to right with the characters
  reversed against their layout.
- The provider follows `prefers-color-scheme`, which is a reader's accessibility setting on many
  systems. Overriding it with a fixed `initialTheme` is a choice worth making deliberately.
