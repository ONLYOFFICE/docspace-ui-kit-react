# ContextMenuButton

Icon that opens a menu of actions, from `data` or from a callback called each time it opens. It
is the "more" button of a row, a card or a toolbar.

## Use this when / not when

- Use for the "more" button of a row, a card or a toolbar, whose actions depend on the current
  selection.
- Not for a right-click menu on a region — that is [`ContextMenu`](../context-menu/README.md),
  which this one opens for [`Row`](../rows/row/README.md) in its `toggle` mode.
- Not for choosing a value: [`ComboBox`](../combobox/README.md).
- Not for a menu you control yourself — [`DropDown`](../drop-down/README.md) anchored to an
  [`IconButton`](../icon-button/README.md) of your own is less indirect.

## Import

```ts
import {
  ContextMenuButton,
  ContextMenuButtonDisplayType,
} from "@onlyoffice/apps-ui-kit/components/context-menu-button";
```

Also exported from the root barrel `@onlyoffice/apps-ui-kit`.

Needs `ThemeProvider` from `@onlyoffice/apps-ui-kit/providers/theme` for the icon and menu
colours, and `TranslationProvider` from `@onlyoffice/apps-ui-kit/providers/translation` because
the items are [`DropDownItem`](../drop-down-item/README.md)s.

## Minimal example

`getData` is what the menu is built from, and the component calls it without checking — a
button without one throws on the first click.

```tsx
import { ContextMenuButton } from "@onlyoffice/apps-ui-kit/components/context-menu-button";

export function RowActions({
  onRename,
  onDelete,
}: {
  onRename: () => void;
  onDelete: () => void;
}) {
  return (
    <ContextMenuButton
      title="Actions"
      getData={() => [
        { key: "rename", label: "Rename", onClick: onRename },
        { key: "delete", label: "Delete", onClick: onDelete },
      ]}
    />
  );
}
```

## Recipes

### Open and close the menu from your own state

`opened` opens the menu when it changes. `onClose` reports every close the component performs: a
click outside, Escape, Tab, a second click on the button, or a chosen item.

```tsx
import { useState } from "react";
import { ContextMenuButton } from "@onlyoffice/apps-ui-kit/components/context-menu-button";

export function ControlledActions({ onRename }: { onRename: () => void }) {
  const [open, setOpen] = useState(false);

  return (
    <ContextMenuButton
      opened={open}
      onClose={() => setOpen(false)}
      onClick={() => setOpen(true)}
      getData={() => [{ key: "rename", label: "Rename", onClick: onRename }]}
    />
  );
}
```

### Disable the actions for a read-only user

```tsx
import { ContextMenuButton } from "@onlyoffice/apps-ui-kit/components/context-menu-button";

export function MaybeActions({
  canEdit,
  onRename,
}: {
  canEdit: boolean;
  onRename: () => void;
}) {
  return (
    <ContextMenuButton
      isDisabled={!canEdit}
      title="Actions"
      displayIconBorder
      getData={() => [{ key: "rename", label: "Rename", onClick: onRename }]}
    />
  );
}
```

## Behaviour the types don't state

- **`getData` wins over `data`.** With `getData` the items are built by calling it each time the
  menu opens; without it the menu shows the current `data`.
- **`onClick` reports the opening, not the closing.** In `dropdown` mode it is called when a
  click, Enter, Space or an arrow key opens the menu. A second click that closes it is not
  reported.
- In `toggle` mode `onClick` is called on every click and on Enter or Space.
- **A key press is reported as a click at the button's lower start corner**, bottom-right in
  RTL. The button is its `target` and `currentTarget`, so `ContextMenu.show(e)` places a menu
  under the button.
- The component is memoised with a shallow comparison. A new handler or `getData` on every
  render re-renders it like any other component.
- **`displayType="auto"` is `dropdown`.** The function that would choose by width returns
  `dropdown` unconditionally. `toggle` is the one that differs: no menu is rendered at all and
  `onClick` is left to open one, which is how [`Row`](../rows/row/README.md) uses it.
- The menu gets a transparent backdrop only on a tablet or a phone. On a desktop, `click` and
  `mousedown` listeners catch a click outside instead.
- The icon is the kit's vertical dots unless `iconName` gives a URL, which is fetched at
  runtime.

## CSS variables

| Variable             | Default               | Effect                                     |
| -------------------- | --------------------- | ------------------------------------------ |
| `--cmb-size`         | `32px`                | Width and height of the bordered box       |
| `--cmb-radius`       | `3px`                 | Corner radius of that box                  |
| `--cmb-icon-padding` | `6px 7px`             | Padding between the border and the icon    |
| `--cmb-border`       | a theme grey, no line | Border of the box, as a `border` shorthand |
| `--cmb-hover-border` | theme grey            | Colour of the border on hover              |

All five apply only with `displayIconBorder`, and can be set on any ancestor. The theme's value
for `--cmb-border` is a colour with no width or style, so by default the box draws no line.
`--cmb-hover-border` shows nothing until `--cmb-border` supplies a style, as in `1px solid`.

The menu is a [`DropDown`](../drop-down/README.md) and reads its own `--dropdown-*` variables. By
default it is portalled to `document.body`, outside the wrapper, so set them there. Or pass
`usePortal={false}` to keep the menu inside the element that sets them.

The icon colour is set inline by the icon itself. Change it with `color`, `hoverColor` and
`clickColor`, not with a variable.

## Accessibility

- The icon is an [`IconButton`](../icon-button/README.md) given `role="button"` and `tabIndex` 0
  (-1 while `isDisabled`). Its `aria-label` is a passed `aria-label`, then `title`, then the
  translated "More options".
- It follows the WAI-ARIA menu button pattern: `aria-haspopup="menu"`, `aria-expanded`, and
  `aria-controls` pointing at the open menu. The menu is `role="menu"` with `role="menuitem"` items.
- `toggle` mode renders no menu, so it sets neither `aria-haspopup` nor `aria-expanded`. Pass
  them, and `aria-controls`, to describe the menu your `onClick` opens.
- Enter, Space and ArrowDown open the menu with focus on the first item, ArrowUp on the last.
- Inside the menu the arrow keys, Home and End move focus. Enter and Space run the item, Escape
  closes the menu, and both return focus to the button. Tab closes it and moves on from the
  button.
- **A passed `aria-*` is kept on the icon**, the element with the role. In `dropdown` mode the
  component sets `aria-haspopup`, `aria-expanded` and `aria-controls` over a passed value.
- The wrapper and the icon both carry `aria-disabled` while `isDisabled`, over a passed value.
