# BaseTile

The tile shell: an icon that turns into a checkbox, a slot for the content, a three-dot menu and a
lower half. [`RoomTile`](../room-tile/README.md) and
[`TemplateTile`](../template-tile/README.md) are this component with their halves filled in; the
file and folder tiles are not, and repeat the same logic separately.

## Use this when / not when

- Use for a tile the kit does not already have — anything that wants the same selection
  behaviour, context menu and two-part layout.
- Not for a file or a folder — [`FileTile`](../file-tile/README.md) and
  [`FolderTile`](../folder-tile/README.md) add the thumbnail and the click-to-select handling that
  this component does not have.
- Not for a room or a template — [`RoomTile`](../room-tile/README.md) and
  [`TemplateTile`](../template-tile/README.md) already wrap this one.
- **A plain click does not select**, unlike on the file and folder tiles. Put your own handler on
  `onRoomClick`.
- **There is no thumbnail.** `thumbnailClick` is in the type and is read by nothing; the picture,
  if you want one, goes in `topContent`.

## Import

```ts
import { BaseTile } from "@onlyoffice/apps-ui-kit/components/tiles/base-tile";
```

Also exported from `@onlyoffice/apps-ui-kit/components/tiles` and from the root barrel
`@onlyoffice/apps-ui-kit`.

`ThemeProvider` switches the tile to its dark colours; without it the tile stays light.
`TranslationProvider` supplies the three-dot button's tooltip, "Show Folder Actions". Without it
the tooltip is empty and the button is named "More options".

## Minimal example

```tsx
import { BaseTile } from "@onlyoffice/apps-ui-kit/components/tiles/base-tile";
import { TileContent } from "@onlyoffice/apps-ui-kit/components/tiles/tile-content";
import { Text } from "@onlyoffice/apps-ui-kit/components/text";

const item = { id: "a1", title: "Quarterly report" };

export function SimpleTile() {
  return (
    <BaseTile
      item={item}
      contextOptions={[]}
      topContent={
        <TileContent>
          <Text truncate>{item.title}</Text>
        </TileContent>
      }
    />
  );
}
```

## Recipes

### Selection

The checkbox is drawn next to `element` and reports through `onSelect`. Hold `checked` yourself:
the tile has no state.

```tsx
import { useState } from "react";

import { BaseTile } from "@onlyoffice/apps-ui-kit/components/tiles/base-tile";
import { TileContent } from "@onlyoffice/apps-ui-kit/components/tiles/tile-content";
import { Text } from "@onlyoffice/apps-ui-kit/components/text";

const item = { id: "a1", title: "Quarterly report" };

export function SelectableTile() {
  const [checked, setChecked] = useState(false);

  return (
    <BaseTile
      item={item}
      checked={checked}
      onSelect={(next) => setChecked(next)}
      contextOptions={[]}
      element={<span aria-hidden="true">📄</span>}
      topContent={
        <TileContent>
          <Text truncate>{item.title}</Text>
        </TileContent>
      }
    />
  );
}
```

### Loading

`inProgress` replaces the icon and the checkbox with the kit's track loader. On its own it is an
indicator, not a lock; `isBlockingOperation`, added here, is what stops the pointer reaching the
tile until the operation ends.

```tsx
import { BaseTile } from "@onlyoffice/apps-ui-kit/components/tiles/base-tile";
import { TileContent } from "@onlyoffice/apps-ui-kit/components/tiles/tile-content";
import { Text } from "@onlyoffice/apps-ui-kit/components/text";

const item = { id: "a1", title: "Uploading…" };

export function BusyTile() {
  return (
    <BaseTile
      item={item}
      inProgress
      isBlockingOperation
      contextOptions={[]}
      element={<span aria-hidden="true">📄</span>}
      topContent={
        <TileContent>
          <Text truncate>{item.title}</Text>
        </TileContent>
      }
    />
  );
}
```

### Add a context menu to a tile

The three-dot button appears when `contextOptions` is non-empty **and** `item` has a
`contextOptions` key of its own. The menu it opens lists `getContextModel`'s entries, so pass that
too; the right-click menu uses it as well.

```tsx
import { BaseTile } from "@onlyoffice/apps-ui-kit/components/tiles/base-tile";
import { TileContent } from "@onlyoffice/apps-ui-kit/components/tiles/tile-content";
import { Text } from "@onlyoffice/apps-ui-kit/components/text";

const options = [{ key: "open", label: "Open", onClick: () => {} }];
// The key on the item is the switch; its value is ignored.
const item = { id: "a1", title: "Quarterly report", contextOptions: [] };

export function TileWithMenu() {
  return (
    <BaseTile
      item={item}
      contextOptions={options}
      getContextModel={() => options}
      element={<span aria-hidden="true">📄</span>}
      topContent={
        <TileContent>
          <Text truncate>{item.title}</Text>
        </TileContent>
      }
    />
  );
}
```

## Behaviour the types don't state

- **The three-dot button needs a `contextOptions` key on `item` as well as the prop.** The key's
  value is never read. `TileItem` does not declare the key, so the types will not remind you.
- Without the key, the tile renders an empty `div.expandButton` where the button would be.
- **Both menus need `getContextModel`.** The menu lists its entries; `contextOptions` only decides
  whether the button is drawn. Without it the button opens nothing.
- **A right-click always stops propagation and calls `tileContextClick(true)`.** Without
  `getContextModel` it swallows the browser's menu and shows none.
- A click on the three-dot button calls `tileContextClick(false)` once.
- **A right-click also clicks `forwardRef`.** Before the menu is mounted, the component
  calls `.click()` on whatever that ref points at. It attaches the ref to nothing itself, so this
  fires a click on an element you own.
- **A tap on the icon selects only in a window 600px wide or narrower.** It always reports `true`,
  so it never clears a selection. On a wider window the same gesture does nothing.
- **The context menu's header comes from the first child of `topContent`.** If that child has an
  `item` prop, its title, icon and logo are used; otherwise the tile's own `item` is. Passing a
  wrapper `div` as the first child therefore changes the menu's header.
- **`element` is the switch for the whole corner.** Without it neither the icon nor the checkbox
  is rendered, so a tile with no `element` cannot be selected at all.
- **The checkbox shows when the pointer is over the icon, not over the whole tile**, and stays
  shown while `checked`. Otherwise it is `display: none`. Under `inProgress` the loader takes the
  corner, so hovering it shows nothing.
- **`isBlockingOperation` is `pointer-events: none` and nothing else.** The tile looks like an idle
  one, so show the operation somewhere else. A ticked checkbox still takes keyboard focus.
- **`isEdit` removes that corner too**, leaving `topContent` the full width for a rename field.
- **`thumbnailClick` is dead** — declared and never read.
- **`onRoomClick` is the tile's `onClick`.** The name is the portal's; it fires on any click
  anywhere in the tile, including on the checkbox.

## CSS variables

Set them through `className` on the tile, or on an ancestor such as the `TileContainer`. The tile
declares only private fallbacks of its own, so an inherited value reaches it.

| Variable              | Default                     | Effect                                                                           |
| --------------------- | --------------------------- | -------------------------------------------------------------------------------- |
| `--tile-bg`           | the theme's tile background | Background of the tile                                                           |
| `--tile-hover-bg`     | the checked background      | Background on hover (except under `isEdit`), when `checked` and under `isActive` |
| `--tile-border-style` | the theme's room border     | Border of the tile                                                               |
| `--tile-radius`       | `12px`                      | Corner radius                                                                    |
| `--tile-padding`      | `16px 0`                    | Padding of the tile                                                              |
| `--tile-row-gap`      | `16px`                      | Gap between the upper and lower halves                                           |
| `--tile-icon-color`   | the theme's icon colour     | Fill of the three-dot button                                                     |
| `--tile-hotkey-color` | the theme's hotkey colour   | Colour of the keyboard outline                                                   |

## Accessibility

- The tile is a plain `<div>` with click and context-menu handlers: no role, no `tabindex`, no key
  handling. The keyboard reaches the three-dot button and whatever you put in the two halves.
- **An unselected tile cannot be selected from the keyboard.** The checkbox is `display: none`
  until the pointer is on the icon, so Tab reaches it only while `checked`.
- The checkbox is the kit's `Checkbox`, a real input, but it carries no label. Name the item in the
  content, or mark the tiles up as a list yourself.
- The three-dot button is named by its tooltip, "Show Folder Actions". Without a translation
  provider the tooltip is empty and the button is named "More options".
- `inProgress` sets `aria-busy="true"` on the tile, and its loader is decorative, so the tile
  announces the busy state once.
- `isBlockingOperation` sets neither `aria-busy` nor `aria-disabled`. It turns off the pointer, not
  the keyboard, so a blocked tile's ticked checkbox can still be toggled.
- The right-click menu is pointer-only. The three-dot button is the keyboard path to the same
  actions, so keep it available.
- The props take no `aria-*`, and the tile forwards nothing it does not name. Label the tile
  through an element of your own in `topContent`.
