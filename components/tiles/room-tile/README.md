# RoomTile

Tile for a room: the logo and name on top, and the room's tags along the bottom. It is
[`BaseTile`](../base-tile/README.md) with a tag row built for it. The tag row is what makes it
worth using over a tile of your own.

## Use this when / not when

- Use for a room in a tile listing, where the tags and the room type should be visible and
  clickable.
- Not for a folder or a document — [`FolderTile`](../folder-tile/README.md) and
  [`FileTile`](../file-tile/README.md).
- Not for a template — [`TemplateTile`](../template-tile/README.md) shows the owner and the
  storage instead of tags.
- Not for a card of your own — [`BaseTile`](../base-tile/README.md) is the same shell with an
  empty lower half.
- **Four props are required and have no sensible empty value**: `columnCount`, `selectTag`,
  `selectOption` and `getRoomTypeName`.
- `getRoomTypeName` turns a room type into a readable label, since the kit does not know the
  portal's room types.

## Import

```ts
import { RoomTile } from "@onlyoffice/apps-ui-kit/components/tiles/room-tile";
```

`components/index.ts` does not list this folder, but it re-exports `tiles` with `export *`. So
the name also arrives from `@onlyoffice/apps-ui-kit/components/tiles` and from the root barrel.

Needs `ThemeProvider` for its colours. `TranslationProvider` supplies two labels: the three-dot
button's tooltip, and the `NoTags` tag an AI agent without tags gets.

## Minimal example

```tsx
import { RoomTile } from "@onlyoffice/apps-ui-kit/components/tiles/room-tile";
import { TileContent } from "@onlyoffice/apps-ui-kit/components/tiles/tile-content";
import { Text } from "@onlyoffice/apps-ui-kit/components/text";

const room = {
  id: "r1",
  title: "Marketing",
  roomType: "2",
  isRoom: true,
  contextOptions: [],
};

export function SimpleRoomTile() {
  return (
    <RoomTile
      item={room}
      contextOptions={[]}
      columnCount={2}
      selectTag={() => {}}
      selectOption={() => {}}
      getRoomTypeName={(type) => (type === "2" ? "Collaboration room" : "Room")}
    >
      <TileContent>
        <Text truncate>{room.title}</Text>
      </TileContent>
    </RoomTile>
  );
}
```

## Recipes

### Open the room on a click

`thumbnailClick` is the tile's open handler, despite its name. It fires on a click anywhere on the
tile except the checkbox, the tag row, the badges and the menu.

```tsx
import { RoomTile } from "@onlyoffice/apps-ui-kit/components/tiles/room-tile";
import { TileContent } from "@onlyoffice/apps-ui-kit/components/tiles/tile-content";
import { Text } from "@onlyoffice/apps-ui-kit/components/text";

const room = {
  id: "r1",
  title: "Marketing",
  roomType: "2",
  contextOptions: [],
};

export function OpenableRoomTile({ open }: { open: () => void }) {
  return (
    <RoomTile
      item={room}
      contextOptions={[]}
      columnCount={2}
      thumbnailClick={open}
      selectTag={() => {}}
      selectOption={() => {}}
      getRoomTypeName={() => "Collaboration room"}
    >
      <TileContent>
        <Text truncate>{room.title}</Text>
      </TileContent>
    </RoomTile>
  );
}
```

### Filter the listing by a clicked tag

A room with tags of its own shows them in the bottom row. A room without gets one generated tag
carrying its type. A click on the room's own tag calls `selectTag`; a click on a generated one
calls `selectOption` with its kind.

```tsx
import { RoomTile } from "@onlyoffice/apps-ui-kit/components/tiles/room-tile";
import { TileContent } from "@onlyoffice/apps-ui-kit/components/tiles/tile-content";
import { Text } from "@onlyoffice/apps-ui-kit/components/text";

const room = {
  id: "r1",
  title: "Marketing",
  roomType: "2",
  tags: [{ label: "Q4", roomType: 2 }],
  contextOptions: [],
};

export function FilterableRoomTile({
  filterByTag,
  filterByType,
}: {
  filterByTag: (label: string) => void;
  filterByType: (value: string) => void;
}) {
  return (
    <RoomTile
      item={room}
      contextOptions={[]}
      columnCount={2}
      selectTag={(tag) => filterByTag(String(tag.label))}
      selectOption={(option) => filterByType(option.value)}
      getRoomTypeName={() => "Collaboration room"}
    >
      <TileContent>
        <Text truncate>{room.title}</Text>
      </TileContent>
    </RoomTile>
  );
}
```

### Replace the tag row with your own content

`customBottomContent` replaces the tag row entirely. Each render calls it with the hover state and
the tags the tile worked out, to lay out your own way.

```tsx
import { RoomTile } from "@onlyoffice/apps-ui-kit/components/tiles/room-tile";
import { TileContent } from "@onlyoffice/apps-ui-kit/components/tiles/tile-content";
import { Text } from "@onlyoffice/apps-ui-kit/components/text";

const room = {
  id: "r1",
  title: "Marketing",
  roomType: "2",
  contextOptions: [],
};

export function RoomTileWithFooter() {
  return (
    <RoomTile
      item={room}
      contextOptions={[]}
      columnCount={2}
      selectTag={() => {}}
      selectOption={() => {}}
      getRoomTypeName={() => "Collaboration room"}
      customBottomContent={(isHovered, tags) => (
        <Text fontSize="12px">
          {isHovered ? "Open room" : `${tags.length} tag(s)`}
        </Text>
      )}
    >
      <TileContent>
        <Text truncate>{room.title}</Text>
      </TileContent>
    </RoomTile>
  );
}
```

## Behaviour the types don't state

- **`thumbnailClick` is the tile's click handler, not a thumbnail's.** There is no thumbnail here.
  A click on a tag selects the tag and does not open the room.
- It skips clicks inside `.checkbox`, `.tags`, `.room-tags`, `.tag`, `.advanced-tag`, `.badges`,
  `#modal-dialog`, `.expandButton` and `.p-contextmenu`. A click on the logo's corner is skipped
  too.
- **The bottom row is always populated.** With `item.tags` it shows them. Without, it shows one
  generated tag with the room type from `getRoomTypeName`, or a `NoTags` label for an AI agent.
- **A third-party room gets an extra tag first**, built from `providerKey` or `providerType`.
  Clicking it calls `selectOption` with `typeProvider`.
- **The room-type tag of a room with no tags calls `selectOption`** with `defaultTypeRoom` and
  `item.roomType`. It never reaches `selectTag`.
- **`selectTag` is called for each of the room's own tags**, plain strings included, with
  `{ label, roomType, providerType }`. A tag object with its own `onClick` calls that instead.
- On an AI agent with no tags of its own, the `NoTags` label reaches neither callback.
- **The menu's own props are missing from this type.** `hideContextMenu` and `tileContextClick`
  reach the base tile, but `RoomTileProps` declares neither, so TypeScript rejects them.
- Without `hideContextMenu` there is no typed way to learn that the menu closed.
- **A plain click does not select.** Unlike the file and folder tiles, selection here is the
  checkbox, or a tap on the logo at 600px or narrower.
- **The three-dot button needs a `contextOptions` key on the item as well as the prop.**
- **Both menus show `getContextModel`'s entries.** Without it neither the three-dot button nor a
  right-click opens anything; `contextOptions` only decides whether the button is drawn.
- See [`BaseTile`](../base-tile/README.md), which this component wraps, for the shared behaviour.
- **Only the first child is rendered**, above the badges; the rest of `children` is dropped.
- **`isBlockingOperation` turns off the pointer and nothing else.** Hover, clicks and right-clicks
  stop reaching the tile, but it looks like an idle one, so show the operation elsewhere.
- **`element` is the switch for the whole corner**: without it neither the logo nor the checkbox
  is rendered, and the tile cannot be selected.

## CSS variables

Set them on an ancestor of the tile. The tile takes no `style` or `className` of its own, and it
does not declare these names, so the ancestor's values reach it.

| Variable              | Default                                         | Effect                                                                                    |
| --------------------- | ----------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `--tile-bg`           | the theme's tile background                     | Background of the tile, and of the box behind the logo                                    |
| `--tile-hover-bg`     | the checked background                          | Background of the tile on hover, when `checked` and under `isActive`                      |
| `--tile-tag-hover-bg` | white; the checked background in the dark theme | Background of the tags on hover (not under `isEdit`), when `checked` and under `isActive` |
| `--tile-icon-color`   | the theme's icon colour                         | Fill of the three-dot button and of a pin badge (`.is-pinned` inside `.badges`)           |
| `--tile-border-style` | the theme's room border                         | Border of the tile                                                                        |
| `--tile-radius`       | `12px`                                          | Corner radius                                                                             |
| `--tile-padding`      | `16px 0`                                        | Padding of the tile                                                                       |
| `--tile-row-gap`      | `16px`                                          | Gap between the name row and the tag row                                                  |
| `--tile-hotkey-color` | the theme's hotkey colour                       | Border colour under `showHotkeyBorder`                                                    |

All but `--tile-tag-hover-bg` and the logo box are read by [`BaseTile`](../base-tile/README.md),
which this component wraps; its section has the details. Hovering the tile also underlines the
name when the content is a link, and that underline has no variable.

## Accessibility

- The tile is a plain `<div>` with click and context-menu handlers: no role, no `tabindex`, no key
  handling. The checkbox and whatever you put in the content are the only focusable parts.
- The tags are the kit's [`Tags`](../../tags/README.md), a group named "Tags". Each tag is a button
  on the tab order that Enter or Space activates, so filtering works from the keyboard.
- `thumbnailClick` is not reachable from the keyboard. Make the room's name a real link if the
  room has to open without a mouse.
- The generated tag is the only place the room type is stated. It is a label, not an accessible
  description of the tile.
- `inProgress` sets `aria-busy="true"` on the tile.
- **A passed `aria-*` lands on the base tile's outer element and is kept.** A passed `aria-label` or `aria-labelledby` makes it a `role="group"`, so the name is read.
