# DatePicker

Button that becomes a removable chip once a date is chosen, with a calendar behind it. It is
[`Calendar`](../calendar/README.md) wrapped in an [`AddButton`](../add-button/README.md) and a
[`SelectedItem`](../selected-item/README.md).

## Use this when / not when

- Use for an optional date in a filter or a form, where "no date" is a normal state. The chosen
  date reads as a removable chip.
- Not for a date that is always present. The unchosen state is a "Select date" button, not an
  empty field, and there is no label or border.
- Not for a date **and** a time — [`DateTimePicker`](../date-time-picker/README.md) is that.
- Not when you want the grid on the page; use [`Calendar`](../calendar/README.md) directly.

## Import

```ts
import { DatePicker } from "@onlyoffice/apps-ui-kit/components/date-picker";
```

Also exported from the root barrel `@onlyoffice/apps-ui-kit`.

Needs `ThemeProvider` from `@onlyoffice/apps-ui-kit/providers/theme`.

Dates are Luxon `DateTime` objects.

## Minimal example

**`outerDate` is what makes the chosen date stick.** Hold the date yourself, set it from
`onChange`, and pass it back in.

```tsx
import { useState } from "react";
import { DateTime } from "luxon";
import { DatePicker } from "@onlyoffice/apps-ui-kit/components/date-picker";

export function DueDateFilter() {
  const [due, setDue] = useState<DateTime | null>(null);

  return (
    <DatePicker
      locale="en"
      openDate={DateTime.now()}
      outerDate={due}
      onChange={setDue}
      selectDateText="Due date"
    />
  );
}
```

## Recipes

### Limit the date to the next three months

`onChange` is called with `null` when the chip's cross is clicked; `hideCross` removes that
cross when the date must not be cleared.

```tsx
import { useState } from "react";
import { DateTime } from "luxon";
import { DatePicker } from "@onlyoffice/apps-ui-kit/components/date-picker";

export function DeliveryDate() {
  const [date, setDate] = useState<DateTime | null>(null);

  return (
    <div>
      <DatePicker
        locale="en"
        openDate={DateTime.now()}
        minDate={DateTime.now().startOf("day")}
        maxDate={DateTime.now().plus({ months: 3 })}
        outerDate={date}
        onChange={setDate}
        selectDateText="Choose a delivery date"
        autoPosition
      />
      {date ? <p>Delivering {date.toFormat("dd MMM yyyy")}</p> : null}
    </div>
  );
}
```

## Behaviour the types don't state

- **`outerDate` is the real value prop, and it is optional in the type.** An effect clears the
  component's own date whenever `outerDate` is empty.
- Without `outerDate` the chip never appears: you pick a day, `onChange` fires, and the control
  drops straight back to its button. `initialDate` alone does not survive that effect either.
- **The chosen date is formatted `dd MMM yyyy`, and there is no format prop.** The month name is
  written in `locale`.
- **The calendar closes on any pick.** Choosing a day calls `onChange` and closes, so there is no
  way to change your mind inside the popup.
- **`minDate`'s own day stays selectable, whatever its time**, as in
  [`Calendar`](../calendar/README.md).
- **Outside clicks are caught in the capture phase on the document.** Scrollbar thumbs are the
  exception, so dragging the calendar's scrollbar does not dismiss it.
- **`autoPosition` is measured once, as the calendar opens**, against a fixed 340px of room to
  the right. Resizing the window while it is open does not move it.
- **`useMaxTime` only applies while nothing is chosen.** Once a date is held, re-picking keeps
  its time instead of the end of the day.
- The wrapper has `role="presentation"`, and the unchosen state is a `<div role="button">` around
  an `AddButton`.
- The `AddButton` sits in an `aria-hidden` span, so the selector is the only button named
  `selectDateText`.
- There is no disabled state and no error state; neither is a prop.

## Accessibility

- The "select date" control is a `<div role="button">` with `tabIndex={0}`, an `aria-label` and
  `aria-expanded`. Enter and Space toggle the calendar, as a click does. The `AddButton` drawn
  inside it is `aria-hidden`, so a screen reader meets one button, not two.
- The calendar's days are native buttons (see [`Calendar`](../calendar/README.md)). After Enter
  opens the calendar, Tab reaches the days, and Enter or Space picks one and closes it.
- Focus is not moved into the calendar when it opens; it follows the selector in the tab order.
  Escape does not close it.
- The chip's clearing cross comes from [`SelectedItem`](../selected-item/README.md) and inherits
  whatever name that gives it.
- `aria-expanded` is set on the select-date control, but not on the chip. Once a date is chosen,
  nothing announces that the calendar can be reopened.
- **A passed `aria-*` lands on the select-date control and is kept.** A passed `aria-label` wins
  over `selectDateText`; `aria-expanded` stays the component's.
- **Once a date is chosen, the chip carries none of them.** It is a `SelectedItem` with no role,
  so the picker does not hand them on.
