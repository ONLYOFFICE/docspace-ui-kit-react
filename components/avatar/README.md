# Avatar

Round picture of a person or a group, falling back to initials, with an optional role badge and
an edit menu. `size` and `role` are both required, and `role` is how you say "no badge".

## Use this when / not when

- Use wherever a person or a group is named: a member list, a row, the author of a comment, a
  profile page.
- Not for a room or a file — that is [`RoomIcon`](../room-icon/README.md), which is square and
  takes a room's colour and logo.
- Not as a plain icon holder: its box is one of seven fixed sizes, and an `.svg` source is
  recoloured grey.
- Not while the person is still loading: [`CircleSkeleton`](../circle/README.md) is the round
  placeholder.

## Import

```ts
import {
  Avatar,
  AvatarRole,
  AvatarSize,
} from "@onlyoffice/apps-ui-kit/components/avatar";
```

Also exported from the root barrel `@onlyoffice/apps-ui-kit`.

Needs `ThemeProvider` from `@onlyoffice/apps-ui-kit/providers/theme` above it in the tree. The
backgrounds, the initials' colour and the badge colours come from the theme. The built-in
illustration has a light and a dark version, picked by the theme.

## Minimal example

With no `source`, the initials of `userName` are drawn instead. `AvatarRole.none` is the way to
ask for no badge.

```tsx
import {
  Avatar,
  AvatarRole,
  AvatarSize,
} from "@onlyoffice/apps-ui-kit/components/avatar";

export function MemberAvatar({ name }: { name: string }) {
  return (
    <Avatar size={AvatarSize.base} role={AvatarRole.none} userName={name} />
  );
}
```

## Recipes

### A picture, with a role badge

Only `owner` and `admin` draw a badge; the other members of `AvatarRole` render nothing.

```tsx
import {
  Avatar,
  AvatarRole,
  AvatarSize,
} from "@onlyoffice/apps-ui-kit/components/avatar";

export function OwnerAvatar({ photo, name }: { photo: string; name: string }) {
  return (
    <Avatar
      size={AvatarSize.medium}
      role={AvatarRole.owner}
      source={photo}
      userName={name}
      withTooltip
      tooltipContent="Room owner"
    />
  );
}
```

### A group

```tsx
import {
  Avatar,
  AvatarRole,
  AvatarSize,
} from "@onlyoffice/apps-ui-kit/components/avatar";

export function GroupAvatar({ title }: { title: string }) {
  return (
    <Avatar
      size={AvatarSize.big}
      role={AvatarRole.none}
      userName={title}
      isGroup
    />
  );
}
```

### Editable, with an upload menu

`editing` is read at `size` `max` only, and the first entry of `model` is the upload action.

```tsx
import {
  Avatar,
  AvatarActionKeys,
  AvatarRole,
  AvatarSize,
} from "@onlyoffice/apps-ui-kit/components/avatar";

export function ProfileAvatar({
  photo,
  onFile,
  onRemove,
}: {
  photo?: string;
  onFile: () => void;
  onRemove: () => void;
}) {
  return (
    <Avatar
      size={AvatarSize.max}
      role={AvatarRole.none}
      source={photo}
      isDefaultSource
      editing
      hasAvatar={Boolean(photo)}
      onChangeFile={onFile}
      model={[
        {
          key: AvatarActionKeys.PROFILE_AVATAR_UPLOAD,
          label: "Upload a photo",
          icon: "",
          onClick: (ref) => ref?.current?.click(),
        },
        {
          key: AvatarActionKeys.PROFILE_AVATAR_DELETE,
          label: "Remove",
          icon: "",
          onClick: onRemove,
        },
      ]}
    />
  );
}
```

## Behaviour the types don't state

- **The first match fills the circle.** In order: a `source` element; a `source` string; the
  initials of `userName`; the illustration of `isDefaultSource`; and failing all of those, a grey
  camera.
- **A `source` string is a picture unless its URL says otherwise.** A path ending in `.svg` is
  fetched and drawn as a grey icon. A URL containing `default_user_photo` becomes the kit's
  illustration.
- **An SVG source is told apart by its URL's path, not by a substring.** `photo.svg.png`,
  `?file=x.svg` and a `#…svg` fragment are pictures. A `data:` URL is always a picture, an inline
  SVG one included; `isNotIcon` draws an `.svg` file as a picture too.
- **Only `owner` and `admin` have a badge.** The other members of `AvatarRole` draw nothing, so a
  `user` avatar and a `none` avatar look the same. Pass `roleIcon` for a badge of your own.
- **`editing` is ignored below `size="max"`.** The edit button and its menu render only at 124px.
  At every other size the role badge takes that corner.
- **`onClick` replaces what a click on the avatar does.** The avatar runs `onClick` _or_ the
  built-in upload behaviour, never both. The edit button keeps its own handler and still opens the
  menu or the file dialog.
- **`noClick` stops the avatar, not the edit button.** A click on the avatar then does nothing
  built-in, but the plus or the pencil still works.
- **`withTooltip` attaches only to the role badge**, so no badge means no tooltip. Its anchor id
  comes from React's `useId`, stable across renders and between server and client.
- **The hidden file input's id is generated per instance**, so two editable avatars never share
  one. Reach the input through the ref the upload entry of `model` is handed, or by its test id.
- **The pencil toggles the menu once per click.** It keeps its click from reaching the avatar's
  own handler, and picking an entry closes the menu without reopening it.
- **`editAction`, `id` and `style` are ignored.** They are declared and never read. `className`
  is the only way in, and it lands on both the outer element and the picture.
- `size` fixes the box: 24, 32, 36, 40, 48, 80 and 124px. The role badge and the initials have
  no rule for `extraSmall`, so that size is for pictures.
- Initials are the first letter of each word of `userName`, two at most. They are uppercased only
  when `isGroup` is set, so "jane doe" stays "jd" for a person.
- In a right-to-left interface the role badge and the edit button sit in the bottom-left corner,
  and the role tooltip opens to the left.
- A middle-button press calls `onClick` as well, through a `mousedown` handler. Enter and Space
  on a focused avatar click it, so `onClick` receives a mouse event either way.
- The component is memoised. `AvatarPure` is the same component without `memo`, exported for
  tests.

## CSS variables

| Variable                      | Default      | Effect                                                                                       |
| ----------------------------- | ------------ | -------------------------------------------------------------------------------------------- |
| `--avatar-radius`             | `50%`        | Corner radius of the avatar and of its picture — square it here                              |
| `--avatar-bg`                 | theme grey   | Background of an avatar with neither `source` nor `userName`: the camera or the illustration |
| `--avatar-initials-bg`        | theme accent | Background behind a person's initials; a group's initials keep their own background          |
| `--avatar-initials-weight`    | `600`        | Weight of a person's initials; a group's stay at `700`                                       |
| `--avatar-owner-fill`         | yellow       | Fill of the owner badge                                                                      |
| `--avatar-administrator-fill` | orange       | Fill of the admin badge                                                                      |

All of them are read inside the avatar and none is declared on it, so set them on an ancestor.
The `style` prop is ignored and cannot carry them.

Behind a `source` the background is a theme colour that none of these overrides. The kit's
illustration stays round whatever `--avatar-radius` says, and so does the edit button.

Each badge also reads `--avatar-owner-stroke` and `--avatar-owner-color`, or their
`administrator` pair, for its outline and its glyph.

## Accessibility

- The avatar is a button only when a click does something: `onClick` is given, or `onChangeFile`
  without `noClick`. Otherwise it has no role and no tab stop.
- As a button it carries `role="button"`, `tabindex="0"` and `aria-label` set to `userName`.
  Enter and Space click it, which opens the edit menu or the file dialog.
- **A passed `aria-*` lands on the avatar and is kept.** A passed `aria-label` wins over
  `userName`.
- A picture's `alt` text is `userName`; with no `userName` it is empty and the picture is
  treated as decorative.
- The edit button is an [`IconButton`](../icon-button/README.md) with an `onClick`, so it is a
  focusable button. It has no accessible name, and it sits inside the avatar's own button.
- Initials are plain text with no label, and the role badge is an inline SVG with none either.
  The badge's meaning is available only as a hover tooltip.
- `tooltipContent` is not translated by the component; pass text you have already translated.
