# DataTable

Columnar list whose header and rows share one grid, with sortable, resizable and hideable columns
whose widths are remembered as shares of the table. It is the successor of
[`Table`](../table/README.md), being built next to it.

## Use this when / not when

- Use for data the user reads across and sorts: files, members, sessions.
- Use `virtualize` for long lists: only the rows in and near the view are rendered. With
  `loadMore` the table asks for the next page as the user nears the end.
- Not for a list of items with one line each — [`Rows`](../rows/README.md) is the portal's own
  list.
- The table does not hold column visibility. It reads each column's `visible` and reports the
  user's choice through `onColumnVisibilityChange`; keeping that choice is the consumer's job.

## Import

```ts
import { DataTable } from "@onlyoffice/apps-ui-kit/components/data-table";
```

The table is **not in the root barrel** while it is being trialled, so it is not part of the
plugin API; import it by subpath.

Needs `ThemeProvider` from `@onlyoffice/apps-ui-kit/providers/theme`: the borders and header
colours are set under its `.light` / `.dark` class, and without it they are not drawn.

## Minimal example

```tsx
import { useMemo } from "react";
import {
  DataTable,
  type DataTableColumn,
} from "@onlyoffice/apps-ui-kit/components/data-table";

type Member = { id: string; name: string; role: string };

export function MemberTable({ members }: { members: Member[] }) {
  const columns = useMemo<DataTableColumn<Member>[]>(
    () => [
      {
        id: "Name",
        title: "Name",
        width: { type: "fill" },
        cell: (member) => member.name,
      },
      {
        id: "Role",
        title: "Role",
        width: { type: "flex" },
        cell: (member) => member.role,
      },
    ],
    [],
  );

  return (
    <DataTable
      columns={columns}
      rows={members}
      getRowKey={(member) => member.id}
      ariaLabel="Members"
    />
  );
}
```

## Recipes

### Sorting

The table never sorts rows. It marks the column whose `sortKey` equals `sort.key` and reports a
click on a sortable header; the consumer re-sorts or refetches.

```tsx
import { useState } from "react";
import {
  DataTable,
  type DataTableColumn,
  type DataTableSort,
} from "@onlyoffice/apps-ui-kit/components/data-table";

type Session = { id: string; device: string; lastSeen: string };

const COLUMNS: DataTableColumn<Session>[] = [
  {
    id: "Device",
    title: "Device",
    width: { type: "fill" },
    sortKey: "device",
    cell: (session) => session.device,
  },
  {
    id: "LastSeen",
    title: "Last seen",
    width: { type: "flex" },
    sortKey: "lastSeen",
    cell: (session) => session.lastSeen,
  },
];

export function Sessions({ sessions }: { sessions: Session[] }) {
  const [sort, setSort] = useState<DataTableSort>({
    key: "lastSeen",
    desc: true,
  });

  return (
    <DataTable
      columns={COLUMNS}
      rows={sessions}
      getRowKey={(session) => session.id}
      sort={sort}
      onSortChange={(key) =>
        setSort((prev) => ({
          key,
          desc: prev.key === key ? !prev.desc : false,
        }))
      }
    />
  );
}
```

A column the rows can be sorted by elsewhere, in a sort menu, but not from its header takes
`sortable: false` with its `sortKey`: the header shows the sort and is not a button, and sorting
by it still turns the column on when it is hidden.

### Remembering the widths

`createLocalStorageWidths(key)` keeps the widths in `localStorage` under `key`, which has to be
unique per table and per user. Without `widthStorage` the table works the same and forgets.

```tsx
import { useMemo } from "react";
import {
  DataTable,
  type DataTableColumn,
  createLocalStorageWidths,
} from "@onlyoffice/apps-ui-kit/components/data-table";

type Doc = { id: number; title: string; size: string };

const COLUMNS: DataTableColumn<Doc>[] = [
  {
    id: "Title",
    title: "Title",
    width: { type: "fill" },
    cell: (d) => d.title,
  },
  { id: "Size", title: "Size", width: { type: "flex" }, cell: (d) => d.size },
];

export function Docs({ docs, userId }: { docs: Doc[]; userId: string }) {
  const widthStorage = useMemo(
    () => createLocalStorageWidths(`docsColumnsWidths=${userId}`),
    [userId],
  );

  return (
    <DataTable
      columns={COLUMNS}
      rows={docs}
      getRowKey={(doc) => doc.id}
      widthStorage={widthStorage}
    />
  );
}
```

### Choosing columns

`settingsColumn` adds the settings button to the header, as a 24 px `fixed` column. Its menu lists
the columns marked `hideable` and reports a tick or untick; the consumer keeps the choice and sets
`visible`.

```tsx
import { useMemo, useState } from "react";
import {
  DataTable,
  type DataTableColumn,
  settingsColumn,
} from "@onlyoffice/apps-ui-kit/components/data-table";

type Guest = { id: string; name: string; email: string; invited: string };

const ALL: DataTableColumn<Guest>[] = [
  { id: "Name", title: "Name", width: { type: "fill" }, cell: (g) => g.name },
  {
    id: "Email",
    title: "Email",
    width: { type: "flex" },
    hideable: true,
    cell: (g) => g.email,
  },
  {
    id: "Invited",
    title: "Invited",
    width: { type: "flex" },
    hideable: true,
    cell: (g) => g.invited,
  },
];

export function Guests({ guests }: { guests: Guest[] }) {
  const [hidden, setHidden] = useState<string[]>([]);

  const columns = useMemo(
    () => [
      ...ALL.map((c) => ({ ...c, visible: !hidden.includes(c.id) })),
      settingsColumn<Guest>({ title: "Choose columns" }),
    ],
    [hidden],
  );

  return (
    <DataTable
      columns={columns}
      rows={guests}
      getRowKey={(guest) => guest.id}
      onColumnVisibilityChange={(id, visible) =>
        setHidden((prev) =>
          visible ? prev.filter((x) => x !== id) : [...prev, id],
        )
      }
    />
  );
}
```

### Row state and the row menu

`getRowProps` gives each row its state and handlers. A row's `contextMenu` opens on a right-click
anywhere in the row, and from a button in the menu column:
`settingsColumn({ withContextMenu: true })` puts the button under the settings button, as the old
table did, and `contextMenuColumn()` gives it a column of its own. Without either column there is
no menu.

```tsx
import { useCallback, useState } from "react";
import {
  DataTable,
  type DataTableColumn,
  type DataTableRowState,
  settingsColumn,
} from "@onlyoffice/apps-ui-kit/components/data-table";

type Task = { id: number; title: string; owner: string };

const COLUMNS: DataTableColumn<Task>[] = [
  {
    id: "Title",
    title: "Title",
    width: { type: "fill" },
    cell: (t) => t.title,
  },
  {
    id: "Owner",
    title: "Owner",
    width: { type: "flex" },
    cell: (t) => t.owner,
  },
  settingsColumn<Task>({ title: "Choose columns", withContextMenu: true }),
];

export function Tasks({
  tasks,
  onDelete,
}: {
  tasks: Task[];
  onDelete: (id: number) => void;
}) {
  const [selected, setSelected] = useState<number | null>(null);

  const getRowProps = useCallback(
    (task: Task): DataTableRowState => ({
      checked: selected === task.id,
      onClick: () => setSelected(task.id),
      contextMenu: {
        title: "Actions",
        options: [
          { key: "delete", label: "Delete", onClick: () => onDelete(task.id) },
        ],
      },
    }),
    [selected, onDelete],
  );

  return (
    <DataTable
      columns={COLUMNS}
      rows={tasks}
      getRowKey={(task) => task.id}
      getRowProps={getRowProps}
    />
  );
}
```

### What a row looks like in each state

The table draws every state of a row itself; the consumer only says which applies. A row in a
state, or under the pointer, stretches its strip past the table into the page's gutters, as far as
`--data-table-row-bleed-start` and `-end` say. `DataTableRowCheckbox` is the item's icon that turns
into the row's checkbox, and `DataTableRowActions` holds what shows only on a row under the
pointer, selected or acted on.

```tsx
import { useCallback } from "react";
import {
  DataTable,
  type DataTableColumn,
  DataTableRowActions,
  DataTableRowCheckbox,
  type DataTableRowState,
} from "@onlyoffice/apps-ui-kit/components/data-table";

type Item = { id: number; title: string; isFolder: boolean };

declare const FolderIcon: () => React.ReactNode;
declare const FileIcon: () => React.ReactNode;

export function Items({
  items,
  selected,
  onSelect,
  cursor,
  dragging,
  running,
}: {
  items: Item[];
  selected: number[];
  onSelect: (id: number, checked: boolean) => void;
  cursor: number | null;
  dragging: boolean;
  running: number[];
}) {
  const columns: DataTableColumn<Item>[] = [
    {
      id: "Name",
      title: "Name",
      width: { type: "fill" },
      cell: (item) => (
        <>
          <DataTableRowCheckbox
            icon={item.isFolder ? <FolderIcon /> : <FileIcon />}
            label={`Select ${item.title}`}
            checked={selected.includes(item.id)}
            loading={running.includes(item.id)}
            onChange={(checked) => onSelect(item.id, checked)}
          />
          {item.title}
          <DataTableRowActions>
            <button type="button">Share</button>
          </DataTableRowActions>
        </>
      ),
    },
  ];

  const getRowProps = useCallback(
    (item: Item): DataTableRowState => ({
      checked: selected.includes(item.id),
      caret: item.id === cursor,
      // A drag owns the pointer: folders take the drop, files fade.
      hover: !dragging,
      dropTarget: dragging && item.isFolder,
      dimmed: dragging && !item.isFolder,
      busy: running.includes(item.id),
    }),
    [selected, cursor, dragging, running],
  );

  // The strips reach across the 20px gutters around the table.
  const gutters = {
    padding: "0 20px",
    "--data-table-row-bleed-start": "20px",
    "--data-table-row-bleed-end": "20px",
  } as React.CSSProperties;

  return (
    <div style={gutters}>
      <DataTable
        columns={columns}
        rows={items}
        getRowKey={(item) => item.id}
        getRowProps={getRowProps}
      />
    </div>
  );
}
```

### Long lists

`virtualize` renders only the rows in and near the view. Name the element that scrolls, or let
the table find the nearest scrolling ancestor; `apiRef` brings a row into view.

```tsx
import { useRef, useState } from "react";
import {
  DataTable,
  type DataTableApi,
  type DataTableColumn,
} from "@onlyoffice/apps-ui-kit/components/data-table";

type LogEntry = { id: number; message: string; at: string };

const COLUMNS: DataTableColumn<LogEntry>[] = [
  {
    id: "Message",
    title: "Message",
    width: { type: "fill" },
    cell: (e) => e.message,
  },
  { id: "At", title: "At", width: { type: "flex" }, cell: (e) => e.at },
];

export function AuditLog({ entries }: { entries: LogEntry[] }) {
  const [scroller, setScroller] = useState<HTMLDivElement | null>(null);
  const apiRef = useRef<DataTableApi>(null);

  return (
    <>
      <button
        type="button"
        onClick={() => apiRef.current?.scrollToIndex(entries.length - 1)}
      >
        Latest
      </button>
      <div ref={setScroller} style={{ height: 600, overflowY: "auto" }}>
        <DataTable
          columns={COLUMNS}
          rows={entries}
          getRowKey={(entry) => entry.id}
          virtualize={{ scrollElement: scroller }}
          apiRef={apiRef}
        />
      </div>
    </>
  );
}
```

### Loading more as the user scrolls

`loadMore` asks for the next page when the view comes within `threshold` rows of the last loaded
one, and draws skeleton rows at the end while there is more. Return the request's promise: the
table does not ask again until it settles.

```tsx
import { useState } from "react";
import {
  DataTable,
  type DataTableColumn,
} from "@onlyoffice/apps-ui-kit/components/data-table";

type Room = { id: number; title: string };

const COLUMNS: DataTableColumn<Room>[] = [
  {
    id: "Title",
    title: "Title",
    width: { type: "fill" },
    cell: (r) => r.title,
  },
];

export function Rooms({
  firstPage,
  total,
  fetchPage,
}: {
  firstPage: Room[];
  total: number;
  fetchPage: (offset: number) => Promise<Room[]>;
}) {
  const [rooms, setRooms] = useState(firstPage);

  return (
    <DataTable
      columns={COLUMNS}
      rows={rooms}
      getRowKey={(room) => room.id}
      virtualize
      loadMore={{
        hasMore: rooms.length < total,
        onLoadMore: async () => {
          const page = await fetchPage(rooms.length);
          setRooms((prev) => [...prev, ...page]);
        },
      }}
    />
  );
}
```

### Wrapping a row

`renderRow` replaces the default row, to wrap it or to compute its state in a component of the
consumer's own — an observer reading a store, a drag-and-drop target. It returns a `DataTableRow`
with the `rowProps` from `getRowProps` spread on it; the row renders the table's cells itself.

```tsx
import type React from "react";
import {
  DataTable,
  type DataTableColumn,
  DataTableRow,
} from "@onlyoffice/apps-ui-kit/components/data-table";

type Item = { id: string; name: string };

const COLUMNS: DataTableColumn<Item>[] = [
  { id: "Name", title: "Name", width: { type: "fill" }, cell: (i) => i.name },
];

export function DroppableItems({
  items,
  onDrop,
}: {
  items: Item[];
  onDrop: (id: string, event: React.DragEvent) => void;
}) {
  return (
    <DataTable
      columns={COLUMNS}
      rows={items}
      getRowKey={(item) => item.id}
      renderRow={({ row, index, rowProps }) => (
        <div
          onDragOver={(event) => event.preventDefault()}
          onDrop={(event) => onDrop(row.id, event)}
        >
          <DataTableRow row={row} index={index} {...rowProps} />
        </div>
      )}
    />
  );
}
```

### Moving from `Table`

The old table is a kit of parts the consumer assembles and keeps in step; this one is one
component given every column. What each part becomes:

| `Table`                                                                      | `DataTable`                                                                     |
| ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `TableContainer` + `TableHeader` + `TableBody`                               | one `DataTable`                                                                 |
| `TableHeader.columns` (`key`, `title`, `enable`, `minWidth`)                 | `columns` (`id`, `title`, `visible`, `width`), with a `cell` renderer each      |
| `enable: false` column still in the grid                                     | `visible: false`, which renders nothing                                         |
| `columnStorageName` + `columnInfoPanelStorageName` (required)                | `widthStorage` (optional), one record whatever the info panel does              |
| `sortBy` + `sorted` + a column's `onClick`                                   | `sort` + `onSortChange`                                                         |
| a column's `onChange` in the settings menu                                   | `hideable` + `onColumnVisibilityChange`                                         |
| `showSettings`, `settingsTitle`                                              | `settingsColumn({ title })` in `columns`                                        |
| `setHideColumns`                                                             | `onCompactChange`                                                               |
| `TableRow` + `TableCell`s per row, `*RowData` components                     | the columns' `cell` renderers; `getRowProps` or `renderRow` for the row         |
| `TableRow.contextOptions`, `getContextModel`, `fileContextClick`             | the row's `contextMenu` (`options`, `getModel`, `onOpen`) + `contextMenuColumn` |
| `selectionProp` on every cell                                                | the row's `cellProps`                                                           |
| `isIndexEditingMode`                                                         | another set of columns                                                          |
| `TableBody` `useReactWindow`, `fetchMoreFiles`, `hasMoreFiles`, `itemHeight` | `virtualize`, `loadMore.onLoadMore`, `loadMore.hasMore`, `rowHeight`            |
| `tagRef` + `withTagRef`                                                      | the column's `headerRef`                                                        |
| reading the last column out of `localStorage`                                | `isLast` in the cell context                                                    |
| the consumer's row styles: hover, selected, hotkey border, `droppable-hover` | the row's `hover`, `checked`, `active`, `caret`, `dropTarget`, `dropOver`       |
| negative margins on the first and last cell for the full-width strip         | `--data-table-row-bleed-start` / `-end`                                         |
| `border-top` + `margin-top: -1px` + 49 px cells for one line between rows    | nothing: rows share one line                                                    |
| `lengthen-header` / `hotkeys-lengthen-header` set from the rows              | nothing: the header follows the first row and the scroll                        |
| `TableCell hasAccess` with `table-container_row-checkbox` inside             | `DataTableRowCheckbox`                                                          |
| `create-share-link` hidden by the old `TableRow`                             | `DataTableRowActions`, or `DATA_TABLE_ROW_ACTIONS_CLASS` on the element         |

Old pixel records are not migrated: the first visit after the switch starts from 40/60.

```tsx
import { useMemo } from "react";
import {
  DataTable,
  type DataTableColumn,
  createLocalStorageWidths,
  settingsColumn,
} from "@onlyoffice/apps-ui-kit/components/data-table";

type File = {
  id: number;
  title: string;
  updated: string;
  contextOptions: string[];
};

export function FilesTable({
  files,
  userId,
  hasMore,
  fetchMoreFiles,
}: {
  files: File[];
  userId: string;
  hasMore: boolean;
  fetchMoreFiles: () => Promise<void>;
}) {
  // What used to be TableHeader's columns and a RowData component, in one place.
  const columns = useMemo<DataTableColumn<File>[]>(
    () => [
      {
        id: "Name",
        title: "Name",
        width: { type: "fill" },
        sortKey: "title",
        cell: (file) => file.title,
      },
      {
        id: "Modified",
        title: "Modified",
        width: { type: "flex" },
        sortKey: "modified",
        hideable: true,
        cell: (file) => file.updated,
      },
      settingsColumn<File>({ title: "Choose columns", withContextMenu: true }),
    ],
    [],
  );

  // One record per table and user, instead of a key and its info-panel twin.
  const widthStorage = useMemo(
    () => createLocalStorageWidths(`filesColumnsWidths=${userId}`),
    [userId],
  );

  return (
    <DataTable
      columns={columns}
      rows={files}
      getRowKey={(file) => file.id}
      widthStorage={widthStorage}
      virtualize
      loadMore={{ hasMore, onLoadMore: fetchMoreFiles }}
    />
  );
}
```

## Behaviour the types don't state

- The header and the rows read one `grid-template-columns` from the `--data-table-grid` custom
  property on the table element. Rows carry no inline grid and read no storage, so they cannot
  lay out differently from the header.
- A `fill` column starts at 40 % of the space left by the `fixed` columns and the `flex` ones
  share 60 %, with minimums of 210 px and 110 px (`DATA_TABLE_MIN_FILL_WIDTH`,
  `DATA_TABLE_MIN_COLUMN_WIDTH`). Flexible tracks are `minmax(<min>px, <share>fr)`, so a window
  resize keeps the proportions without any script running.
- A column with `visible: false` renders nothing, in the header or the rows. When a visible
  column is hidden its share goes to the flexible column on its left; when one appears it takes
  the flexible space divided by the number of flexible columns, itself included, from the widest
  column, or the layout resets to 40/60 if that would break a minimum.
- Widths are stored as shares by column id, `{ "v": 2, "widths": { "<id>": <share> } }`. A
  record of another table, of the old `Table` (a pixel string) or one that cannot be parsed reads
  as nothing stored. Storage that is blocked, full or absent is ignored.
- The table restores the stored record before its first paint, and again only when
  `widthStorage.id` changes. It writes the record only when the user resizes or resets, never by
  rendering, so a second window with the same key does not overwrite the first one's layout.
- A column's trailing edge in the header is a resize handle when the column is resizable and a
  resizable column follows it, so the last flexible column and `fixed` columns have none. Dragging
  it grows the column and shrinks the resizable columns on the side the pointer moves to, nearest
  first, each down to its minimum; the column on the other side of the edge takes the difference.
  The total never changes, so the table never scrolls sideways. `fixed` columns are skipped. Each
  pointer move counts from where the edge is now, so an edge stuck at the minimums waits for the
  pointer to come back to it, and turning back mid-drag widens the edge's neighbour rather than
  the column that was squeezed last.
- During a drag only the `--data-table-grid` property changes, once per animation frame; React
  does not re-render. The widths are committed and stored once, when the pointer is released. A
  cancelled pointer (`pointercancel`) puts the grid back and stores nothing.
- A double click on any edge resets every column to 40/60 and clears the stored record.
- The table's colours follow the nearest `.light` or `.dark` ancestor, so a `dark` wrapper turns
  the table dark on a light page. The settings and row menus open in a portal on `<body>` and
  follow the theme there, which is where `ThemeProvider` puts it.
- In right-to-left the edges sit on the left of each header and both the pointer and the arrow
  keys are mirrored: the edge follows the pointer and the key's visual direction.
- When the columns no longer fit at their minimums — `fixed` sizes plus 210 px for each `fill`
  column and 110 px for each `flex` one — the table turns compact: only `fill` and `fixed`
  columns render, the `fill` ones take the rest with no minimum, resize handles go away and the
  settings button is disabled. Exactly the minimums still fit. The table leaves compact mode as
  soon as the columns fit again, with the proportions they had. `onCompactChange` reports each
  change; a table that mounts compact reports `true`, one that mounts wide reports nothing. A
  container of width 0, such as a hidden section, is never compact.
- The container is watched with a `ResizeObserver`, measured at most once per animation frame,
  so an info panel opening, a window resize or the article collapsing are all handled the same
  way, and none of them writes to the storage.
- When a column's `visible` changes, the new shares are stored, since that change is the user's
  choice. Sorting by a hidden column marked `hideable` calls
  `onColumnVisibilityChange(id, true)` once, when `sort.key` moves to it, so the sorted values
  are on screen.
- The settings menu does not let the last visible flexible column be unticked, and it closes on
  Escape, giving the focus back to its button.
- `isLast` in the cell context is true for the last rendered column that is not `fixed`, so
  trailing content lands before a fixed context-menu column, not in it.
- The header is `position: sticky` at the top of the nearest scrolling ancestor. Each body row is
  `rowHeight` high, 48 px by default (`DATA_TABLE_ROW_HEIGHT`), including the 1 px line below it;
  the header row is 39 px plus a 1 px border. Every row has the same height: the table measures
  none of them.
- With `virtualize`, the rows in view plus `overscan` (5) beyond each edge are in the DOM. Each
  sits in a `div.table-list-item.window-item` placed with `top` — not a transform — inside a
  container as tall as the whole list, which takes `innerClassName`; the portal's selection area,
  hotkeys and the data room's index separator read exactly that markup. The table carries
  `aria-rowcount` and each row `aria-rowindex`, the header counting as row 1.
- The scroller is `virtualize.scrollElement`, else the nearest ancestor whose `overflow-y` is
  `auto`, `scroll` or `overlay`, else the window. Content above the table inside the same
  scroller is allowed: where the body starts is measured on every render and every scroll, so a
  filter bar that grows is caught by the next scroll at the latest.
- With `loadMore` and `hasMore`, `skeletonRows` (2) skeleton rows follow the loaded ones. The
  next page is asked for when the last rendered row is within `threshold` (15) of the last
  loaded one — rendered rows include the overscan — or, without `virtualize`, when the skeleton
  rows come within that distance of their scroller's view. One call per loaded count: while a
  returned promise is pending nothing is asked, a page that brings no rows does not set off
  another call, and a rejected one is retried only when the view moves, never in a loop. A
  page that does not fill the view is followed by the next one as soon as it settles. The body
  carries `aria-busy="true"` while a page loads.
- Skeleton rows are `div.table-container_body-loader` on the same grid as the real rows, with a
  bar in every flexible cell (or the column's `skeleton()`) and fixed cells empty. In a
  virtualised list their wrappers are not `.window-item`s, as in the old table, so nothing
  counts them as items.
- With `virtualize`, a scroll event that moves more than 800 px past the previous one
  (`MAX_INFINITE_LOADER_SHIFT`, the old loader's rule) draws skeleton rows in place of every
  rendered row until the scroll has been calm for 200 ms. `skeletonOnFastScroll: false` keeps the
  real rows.
- `apiRef.scrollToIndex(index)` scrolls a row into view, below the sticky header rather than
  under it, with or without `virtualize`.
- `columns` should be stable between renders: rows are memoised and a new array re-renders all
  of them. The same goes for `getRowProps` and `renderRow`: each row is memoised on its data,
  its index and these two functions, so `getRowProps` runs again only for a row that changed, or
  for all of them when the function does. A cell reading a store that changes on its own (MobX)
  has to be an observer itself; the row does not track what its cells read.
- A row draws its background and its lines on a strip behind its cells. The line above a row lies
  on the line below the previous one, so neighbours share one line and a border never doubles.
  A row under the pointer (unless `hover: false`), `checked`, `active`, `caret`, `dropTarget` or
  `highlight` stretches the strip, lines included, past the table by
  `--data-table-row-bleed-start` / `-end`; the header's background reaches as far, so such a row
  scrolled under the header stays hidden there. Hover tints only where the pointer can hover.
- A row with `checked` gets the `checked` class, `aria-selected="true"` and the selected tint;
  `active` tints it the same way without selecting it. `caret` draws its two lines in the caret
  colour and raises the row over its neighbours so theirs do not cover them; on the first row,
  while the header is not stuck, the header's line takes the caret colour too. `dropTarget` tints
  in the drop colour and `dropOver` in the stronger one, which a `dropTarget` row also takes under
  the pointer, since a drag that moves the pointer itself leaves `:hover` working. A drop tint wins
  over the selected one. `dimmed` fades the cells to 0.4, `busy` makes them ignore the pointer, and
  `highlight` flashes the strip once, over 2 s. A row with `onClick` has the pointer cursor.
- The strip is behind the cells, so a cell's own background covers it; the line below a row is the
  cell's last pixel, which its content is centred above.
- `DataTableRowCheckbox` shows the icon and keeps the checkbox in the same 32 px square, hidden but
  in the tab order. The checkbox shows while the pointer is over the square itself, as the old
  table's did, on a `checked` row and while it has the keyboard focus; `disabled` keeps the icon
  alone and `loading` puts a loader in place of both. The checkbox is the kit's `Checkbox`, which is not controlled: the row's `checked` sets it.
- Content in `DataTableRowActions`, or any element with `DATA_TABLE_ROW_ACTIONS_CLASS`, is
  `display: none` on a row that is not under the pointer, `checked`, `active` or holding the
  focus; where nothing can hover, it always shows.
- `cellProps` goes on every cell of the row: drag and drop finds all the cells of a row by a
  class and reads the `value` attribute, as with the old table's cells.
- A right-click on a row calls its `onContextMenu` first; `preventDefault()` there keeps the
  menu closed. Otherwise `contextMenu.onOpen(true)` is called and the menu opens at the pointer
  (`onOpen(false)` from the button). Before opening, the menu's cell receives a click, as in the
  old table, so that other open menus and click-outside listeners close; that click does not
  reach the row's own `onClick`. The button is drawn only while `options` has items; the cell
  keeps an empty `expandButton` otherwise. The cell has the old
  `table-container_row-context-menu-wrapper` class and does not clip, so the button's focus ring
  shows whole.
- Reordering rows, or any other mode, is a different set of columns rather than a flag: an index
  column with buttons, `settingsColumn({ disabled: true })` and no row menu.
- There is no slot for a group menu over the header: the portal renders it in the section header,
  outside the table.

## CSS variables

Set them on any ancestor of the table. Each default has a light and a dark value, picked by the
`.light` / `.dark` class `ThemeProvider` sets.

| Variable                                | Default (light / dark)      | Effect                                                                  |
| --------------------------------------- | --------------------------- | ----------------------------------------------------------------------- |
| `--data-table-background`               | `#ffffff` / `#333333`       | Background of the sticky header, so rows scroll under it unseen         |
| `--data-table-border-color`             | `#eceef1` / `#474747`       | Line under the header and under every row                               |
| `--data-table-header-text-color`        | `#a3a9ae` / `#858585`       | Header titles, the sort arrow and the settings button                   |
| `--data-table-header-text-hover-color`  | `#657077` / `#ffffff`       | The same under the pointer, and the focus ring of the header's controls |
| `--data-table-resize-color`             | `#d0d5da` / `#474747`       | The resize edges, and the settings button while it is disabled          |
| `--data-table-resize-active-color`      | `#657077` / `#858585`       | A resize edge under the pointer, focused or being dragged               |
| `--data-table-row-hover-background`     | `#f3f4f4` / `#3d3d3d`       | A row under the pointer                                                 |
| `--data-table-row-selected-background`  | `#f3f4f4` / `#3d3d3d`       | A `checked` or `active` row                                             |
| `--data-table-row-drop-background`      | `#e5e48a` at 50 % / at 12 % | A `dropTarget` row                                                      |
| `--data-table-row-drop-over-background` | `#ffefaf` / `#a88f56`       | A `dropTarget` row with `dropOver` or under the pointer                 |
| `--data-table-row-background`           | `transparent`               | Every row's strip, before any state; within the table, not the gutters  |
| `--data-table-row-caret-color`          | `#5299e0`                   | The lines of a `caret` row                                              |
| `--data-table-row-highlight-background` | `#5299e0`                   | Where a `highlight` row's flash starts                                  |

Each of them may also be set on a row, through its `className` or `style`, to recolour that row
alone: a mode that tints every row sets `--data-table-row-background`.

Five more place the sticky header and the strips, and have no theme values. The header's bleeds
say how far its line reaches past the table, at the start and at the end, once rows scroll under
it: into the page's gutters, where a selected row's strip already reaches. The rows' bleeds say how
far a row's strip reaches, and are the header's unless set. The top is for a page that pins
something above the list in the same scroller, such as a filter bar: the header stops below it, and
`scrollToIndex` lands rows below both.

| Variable                       | Default                    | Effect                                                   |
| ------------------------------ | -------------------------- | -------------------------------------------------------- |
| `--data-table-header-top`      | `0px`                      | How far below the scroller's top the header sticks       |
| `--data-table-bleed-start`     | `0px`                      | How far the stuck header's line runs past the start edge |
| `--data-table-bleed-end`       | `0px`                      | How far the stuck header's line runs past the end edge   |
| `--data-table-row-bleed-start` | `--data-table-bleed-start` | How far a row's strip runs past the start edge           |
| `--data-table-row-bleed-end`   | `--data-table-bleed-end`   | How far a row's strip runs past the end edge             |

Row height is the `rowHeight` prop, not a variable: the virtualiser has to know it too.

## Accessibility

The table element has `role="table"`, with `aria-label` from `ariaLabel`. The header and the body
are each a `role="rowgroup"`, every row `role="row"`, header cells `role="columnheader"` and body
cells `role="cell"`. A header with a `sortKey`, when `onSortChange` is given and `sortable` is not
false, holds a native `<button>`, so it is reachable with Tab and sorts on Enter or Space; the
sorted column carries `aria-sort="ascending"` or `"descending"`, button or not. The sort arrow is
decorative (`aria-hidden`).

The settings button is a native `<button>` named by `settingsColumn`'s `title`, with
`aria-haspopup` and `aria-expanded`; its menu items are the kit's `Checkbox`, labelled with each
column's `settingsLabel` or text `title`. Without a `title` the button has no accessible name.

Each resize handle is a focusable `role="separator"` with `aria-orientation="vertical"`, named
after its column (`title` when it is a string, otherwise the column id) and reporting the column's
share of the flexible space as `aria-valuenow` from 0 to 100, with `aria-valuetext` such as
`"40%"`. ArrowLeft and ArrowRight move the edge 10 px, 50 px with Shift; the handle sits outside
the sort button, so it never sorts. A `fixed`
column with an empty `title`, such as a context-menu column, has an empty column header; give it a
`header` renderer with visually hidden text if it needs a name.

A row's menu button is the kit's `ContextMenuButton`, named by `contextMenu.title`; the menu is
the kit's `ContextMenu`, which works from the keyboard. Only the right-click and the button open
it; there is no keyboard shortcut on the row itself.

With `virtualize`, only some rows exist in the DOM, so the table states the full count in
`aria-rowcount` and each row its position in `aria-rowindex`; a screen reader then announces
"row 5 002 of 10 001" rather than a count of what happens to be rendered.

A row given `checked` reports it as `aria-selected`; a row without `checked` carries no
`aria-selected` at all.

`DataTableRowCheckbox` is a native checkbox named by `label`, as `aria-label` and tooltip. While the
icon shows, the checkbox is hidden but stays in the tab order, and shows once it has the focus, so
the keyboard can select rows the pointer never visited; the icon goes into the same square and is
the consumer's to hide from screen readers. Content in `DataTableRowActions` shows as soon as the
focus is anywhere in its row, so Tab moves on into it rather than skipping it.

Skeleton rows are `aria-hidden`, so they are not announced as empty rows; while a page loads the
body carries `aria-busy="true"` instead.
