# ColumnarInfoBar

Bar of label-and-value columns for context the reader does not have to act on. It lays out facts
such as the metadata of a webhook delivery, with an optional caption and close cross.

## Use this when / not when

- Use for a handful of short read-only facts that belong above the content they describe.
- Not for a message that needs a decision — a bar with a button is
  [`PublicRoomBar`](../public-room-bar/README.md) or a dialog.
- Not for something transient that appears after an action — use
  [`Snackbar`](../snackbar/README.md) or `toastr`.
- Not for a block of arbitrary content — [`Card`](../card/README.md) takes children; this
  component takes only the pairs.
- **There is no severity.** The default variant paints a warning-orange edge, and nothing
  switches it to an error or success colour: change `--cib-accent` yourself.

## Import

```ts
import { ColumnarInfoBar } from "@onlyoffice/apps-ui-kit/components/columnar-info-bar";
```

Also exported from the root barrel `@onlyoffice/apps-ui-kit`.

Needs `ThemeProvider` above it in the tree. Every colour it paints is declared only under the
provider's `.light` and `.dark` classes. Without it the bar is transparent text on the page
background.

## Minimal example

```tsx
import { ColumnarInfoBar } from "@onlyoffice/apps-ui-kit/components/columnar-info-bar";

export function DeliveryDetails() {
  return (
    <ColumnarInfoBar
      headerText="Delivery"
      columns={[
        { label: "Status", value: "200 OK" },
        { label: "Event", value: "file.created" },
        { label: "Sent", value: "14:32:01" },
      ]}
    />
  );
}
```

## Props

`columns` is an array of `ColumnarInfoBarColumn`, exported from the same subpath:

| Field   | Type        | Description                                                    |
| ------- | ----------- | -------------------------------------------------------------- |
| `label` | `ReactNode` | Caption above the value, at 12px                               |
| `value` | `ReactNode` | The value, in a flex row with an 8px gap for an icon beside it |

## Recipes

### Dismissing it

`onAction` draws the cross and tells you it was clicked. It does not hide anything — the bar is
on screen for as long as you render it.

```tsx
import { useState } from "react";
import { ColumnarInfoBar } from "@onlyoffice/apps-ui-kit/components/columnar-info-bar";

export function WelcomeDetails({ email }: { email: string }) {
  const [shown, setShown] = useState(true);

  if (!shown) return null;

  return (
    <ColumnarInfoBar
      headerText="Your profile details"
      columns={[
        { label: "Email", value: email },
        { label: "Password", value: "Sent to your inbox" },
      ]}
      onAction={() => setShown(false)}
    />
  );
}
```

### The page variant

`variant="page"` is the block form: rounded, padded, no accent edge, and the columns become a
two-column grid instead of a wrapping row. The header moves up beside the cross.

```tsx
import { ColumnarInfoBar } from "@onlyoffice/apps-ui-kit/components/columnar-info-bar";

export function PlanSummary() {
  return (
    <ColumnarInfoBar
      variant="page"
      headerText="Current plan"
      columns={[
        { label: "Tier", value: "Business" },
        { label: "Seats", value: "25 of 40" },
        { label: "Renews", value: "1 October 2026" },
        { label: "Region", value: "EU West" },
      ]}
    />
  );
}
```

### Recolouring it

There is no `className` prop. The custom properties go through `style`, which is the only
element-level hook the component offers.

```tsx
import type { CSSProperties } from "react";

import { ColumnarInfoBar } from "@onlyoffice/apps-ui-kit/components/columnar-info-bar";

export function ErrorFacts() {
  return (
    <ColumnarInfoBar
      headerText="Import failed"
      columns={[
        { label: "Rows read", value: "1 204" },
        { label: "Rows rejected", value: "37" },
      ]}
      style={
        {
          "--cib-accent": "#f2675a",
          "--cib-header-color": "#f2675a",
        } as CSSProperties
      }
    />
  );
}
```

## Behaviour the types don't state

- **`onLoad` is called once, on mount, and never again.** The effect has an empty dependency
  list, so a different function on a later render is ignored.
- **`onAction` does not close the bar.** It renders the cross and reports the click; removing
  the bar is yours to do.
- **The columns are a wrapping row.** Each label sits above its value, and a column that does not
  fit moves to the next line.
- Below 600px the default and `neutral` variants give every column the full width, so the pairs
  stack.
- **`variant="neutral"` is a card, not a bar**: no accent edge, 8px corners, a 2px light-blue
  border and a blue heading, in both themes.
- **`variant="neutral"` slides open** over 0.4s, from `max-height: 0` to `150px`. Then the cap
  goes, so a taller card jumps to its full height at the end.
- The same variant adds `margin: 4px` and sets its width to `calc(100% - 8px)`.
- **`variant="page"` stays two columns at every width.** The grid is a fixed
  `repeat(2, 1fr)`; only the default and `neutral` variants give each column the full width
  below 600px.
- **There is no `className` prop.** `style` is the only way to reach the element, which is why
  the custom properties are documented as inline values.
- **The close button's hit area differs by variant.** It is 44×44 in the default and `neutral`
  forms, and 12×12 in `page`, where the 16px icon overflows its own button box.
- **The header is an `<h3>`**, whatever the bar's place on the page, so it can leave a gap in
  the heading order. An empty `headerText` renders no element at all.
- **`headerText` is a string only**, while `label` and `value` take any node.

## CSS variables

Set them through `style` on the component.

| Variable             | Default                            | Effect                                                                                               |
| -------------------- | ---------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `--cib-bg`           | a pale warning cream; grey in dark | Background of the bar                                                                                |
| `--cib-color`        | black; white in dark               | Text and close-cross colour, the label at 60% opacity; `page` keeps its own grey for label and cross |
| `--cib-accent`       | the warning orange                 | The 4px leading edge; `transparent` in the other two variants                                        |
| `--cib-header-color` | `--cib-accent`                     | Colour of `headerText`; `neutral` and `page` set their own                                           |

The stylesheet declares `--cib-bg`, `--cib-color` and `--cib-accent` on the bar itself, in both
themes, so a value set on an ancestor never reaches it. `neutral` and `page` declare
`--cib-header-color` too. Only that one, in the default variant, can be inherited.

## Accessibility

- The columns are a description list: a `<dl>` of `<dt>` labels and `<dd>` values, each pair in a
  `<div>`. A screen reader reads each value as the description of its label.
- Keep `label` to phrasing content; a heading inside a `<dt>` is not allowed.
- The close button is a real `<button>`, reached with Tab and pressed with Enter or Space, named
  by `closeLabel`. Without `onAction` there is no button.
- `headerText` renders as an `<h3>`. Check that level against the page around it — the component
  does not adapt it, so a bar placed under an `<h1>` skips `<h2>`.
- The default and `neutral` bars are announced, because they appear in response to something. A
  visually hidden `role="status"` region beside the content carries its text, without the close
  button's name.
- That region stays empty for 100 ms, then takes the text, since a region inserted with its text
  is usually not announced. The bar is announced on appearing and again when its content changes.
- A virtual cursor meets the text twice. The `page` variant is static and announces nothing.
- Nothing here traps focus or moves it.
- **A passed `aria-*` lands on the bar's outer element and is kept.** A passed `aria-label` or `aria-labelledby` makes it a `role="group"`, so the name is read.

## Test ids

The component sets none, on any element. Select it by its text, by `role="button"` for the
cross, or add a `data-testid` to a wrapper of your own.
