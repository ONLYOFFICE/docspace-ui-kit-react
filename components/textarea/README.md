# Textarea

Multi-line text field that grows with its content, with optional line numbers, a copy button
and a JSON mode. It is controlled: the value you pass is what it shows.

## Use this when / not when

- Use for free text of more than one line: a description, a message, a pasted key or document.
- Not for a single line — [`TextInput`](../text-input/README.md) is sized and styled for that,
  and has the mask and password types this one does not.
- Not alone when the field needs a label, a help tooltip or an error message: wrap it in
  [`FieldContainer`](../field-container/README.md).

## Import

```ts
import { Textarea } from "@onlyoffice/apps-ui-kit/components/textarea";
```

Also exported from the root barrel `@onlyoffice/apps-ui-kit`.

Needs `ThemeProvider` from `@onlyoffice/apps-ui-kit/providers/theme` above it in the tree, for
the surface, border and scrollbar colours.

## Minimal example

```tsx
import { useState } from "react";
import { Textarea } from "@onlyoffice/apps-ui-kit/components/textarea";

export function RoomDescription() {
  const [text, setText] = useState("");

  return (
    <Textarea
      value={text}
      aria-label="Room description"
      placeholder="What is this room for?"
      onChange={(e) => setText(e.target.value)}
    />
  );
}
```

## Recipes

### Show a key the user copies but cannot change

`isReadOnly` keeps the field selectable and focusable but refuses edits, and looks like an
editable field. `isDisabled` is different: it greys the field and takes it out of the tab order.

```tsx
import { Textarea } from "@onlyoffice/apps-ui-kit/components/textarea";

export function ApiKeyField({ apiKey }: { apiKey: string }) {
  return (
    <Textarea
      value={apiKey}
      isReadOnly
      enableCopy
      copyInfoText="API key copied"
    />
  );
}
```

### Mark text that is too long

```tsx
import { useState } from "react";
import { Textarea } from "@onlyoffice/apps-ui-kit/components/textarea";

export function CommentField() {
  const [text, setText] = useState("");
  const tooLong = text.length > 280;

  return (
    <Textarea
      value={text}
      hasError={tooLong}
      aria-invalid={tooLong}
      maxLength={400}
      onChange={(e) => setText(e.target.value)}
    />
  );
}
```

### Edit JSON with line numbers

```tsx
import { useState } from "react";
import { Textarea } from "@onlyoffice/apps-ui-kit/components/textarea";

export function WebhookPayload() {
  const [payload, setPayload] = useState('{ "event": "file.created" }');

  return (
    <Textarea
      value={payload}
      isJSONField
      hasNumeration
      enableCopy
      heightScale
      onChange={(e) => setPayload(e.target.value)}
    />
  );
}
```

## Behaviour the types don't state

- **It has a maximum width but no width.** The field caps at `--textarea-width` (1200px) and
  otherwise takes the width the layout gives it. As a flex or grid item, that is the width of its
  content, not of the free space.
- In a flex row it collapses to a sliver that is still focusable and still accepts text.
- **Give it a width through `wrapperClassName`**: `width: 100%`, or `flex: 1 1 auto` with
  `min-width: 0` in a flex container. It is the only prop that reaches the element with the
  max-width.
- **A width in `style` changes nothing.** `style` lands on the inner `Scrollbar`, whose own rule
  is already `width: 100% !important`.
- **`isJSONField` adds its own error state.** The field is red whenever the value is empty or is
  not a JSON object or array, whatever `hasError` says. `42` and `"text"` parse and still count
  as invalid.
- `hasError` still applies on top of that mode, so a field holding valid JSON turns red when you
  pass it.
- Three props are accepted and never read: `minHeight`, `fullHeight` and `paddingLeftProp`. The
  height they suggest comes from `heightTextArea`, `heightScale` and `isFullHeight` instead.
- The default `placeholder` is a single space rather than an empty string, so
  `:placeholder-shown` matches even when no placeholder was asked for.
- A click on the field stops propagating, so a parent listening for clicks does not see it.
- The text direction is `auto`: a value that starts with Arabic or Hebrew renders right to
  left regardless of the interface language.

than 13px puts the line numbers out of step with the lines.

## Accessibility

- Renders a real `<textarea>`, so it is announced as a multi-line field and supports the
  platform's own editing and selection.
- **Name it, one of three ways.** `id` lands on the `<textarea>` itself, so a `FieldContainer`
  with the same string as `labelFor` captions it. That is the one to use when the caption is on
  screen.
- `aria-labelledby` points at any other element that names the field, and `aria-label` covers a
  field with no visible caption. A field named by none of the three is an unnamed edit box.
- **A passed `aria-*` lands on the `<textarea>` and is kept.** The component sets no `aria-*` of
  its own there.
- Besides `aria-*`, `spellCheck`, `autoCorrect`, `autoCapitalize` and `autoComplete`, the type
  accepts no other DOM attribute.
- **`aria-describedby` carries the error or hint.** The component draws an error state in colour
  and nothing more. The message has to be an element of yours that this prop points at.
- `hasError` sets no `aria-invalid`; pass it alongside, as
  [Mark text that is too long](#mark-text-that-is-too-long) does.
- **The copy button is named by the translated "Copy to clipboard".** It is an
  [`IconButton`](../icon-button/README.md), focusable and pressed with Enter or Space.
- It is in the tab order by default.
