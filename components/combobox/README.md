# ComboBox

Button showing the current choice, with a list of options under it. The choice itself stays in
your state: the component reports a click and nothing more.

## Use this when / not when

- Use to pick one value from a short, known list: a role, a time zone, a filter, a language.
- Not for a value the user types or searches: there is no search field. A long list wants
  [`Selector`](../selector/README.md) or an input of your own.
- Not for a menu of actions. A menu is [`DropDown`](../drop-down/README.md) with
  [`DropDownItem`](../drop-down-item/README.md)s; this one is about a value.
- Not on its own in a form: a labelled field is
  [`FieldContainer`](../field-container/README.md) around it.
- Not for many values at once. It shows one option and a `+N` badge you maintain yourself.

## Import

```ts
import {
  ComboBox,
  ComboBoxSize,
} from "@onlyoffice/apps-ui-kit/components/combobox";
```

Also exported from the root barrel `@onlyoffice/apps-ui-kit`.

Needs `ThemeProvider` from `@onlyoffice/apps-ui-kit/providers/theme` for the button and list
colours. It also needs `TranslationProvider` from `@onlyoffice/apps-ui-kit/providers/translation`:
the options are `DropDownItem`s, which read a translated label for their paid badge.

## Minimal example

`selectedOption` and `options` are both required, and `onSelect` is what updates the first.

```tsx
import { useState } from "react";
import {
  ComboBox,
  type TOption,
} from "@onlyoffice/apps-ui-kit/components/combobox";

const ROLES: TOption[] = [
  { key: "viewer", label: "Viewer" },
  { key: "editor", label: "Editor" },
  { key: "owner", label: "Owner" },
];

export function RolePicker() {
  const [role, setRole] = useState<TOption>(ROLES[0]);

  return (
    <div style={{ width: 240 }}>
      <ComboBox
        options={ROLES}
        selectedOption={role}
        onSelect={setRole}
        scaled
        scaledOptions
      />
    </div>
  );
}
```

## Recipes

### Control when the list opens

`opened` seeds the open state rather than owning it, and `onToggle` reports every click on the
button. Pass `onBackdropClick` as well, or a click outside stops closing the list.

```tsx
import { useState } from "react";
import {
  ComboBox,
  type TOption,
} from "@onlyoffice/apps-ui-kit/components/combobox";

const SORTS: TOption[] = [
  { key: "name", label: "Name" },
  { key: "date", label: "Last modified" },
];

export function SortPicker() {
  const [sort, setSort] = useState<TOption>(SORTS[0]);
  const [open, setOpen] = useState(false);

  return (
    <ComboBox
      options={SORTS}
      selectedOption={sort}
      opened={open}
      onToggle={(_event, next) => setOpen(next)}
      onBackdropClick={() => setOpen(false)}
      onSelect={(option) => {
        setSort(option);
        setOpen(false);
      }}
    />
  );
}
```

### Show a spinner while the options load

```tsx
import {
  ComboBox,
  type TOption,
} from "@onlyoffice/apps-ui-kit/components/combobox";

const PLACEHOLDER: TOption = { key: "none", label: "Loading…" };

export function RoomPicker({
  rooms,
  isLoading,
}: {
  rooms: TOption[];
  isLoading: boolean;
}) {
  return (
    <ComboBox
      options={rooms}
      selectedOption={rooms[0] ?? PLACEHOLDER}
      isLoading={isLoading}
      isDisabled={rooms.length === 0}
    />
  );
}
```

### Make a long list scroll

`dropDownMaxHeight` is what gives the list a scrollbar; without it every option is rendered.

```tsx
import { useState } from "react";
import {
  ComboBox,
  type TOption,
} from "@onlyoffice/apps-ui-kit/components/combobox";

export function TimezonePicker({ zones }: { zones: TOption[] }) {
  const [zone, setZone] = useState<TOption>(zones[0]);

  return (
    <ComboBox
      options={zones}
      selectedOption={zone}
      onSelect={setZone}
      dropDownMaxHeight={320}
      displaySelectedOption
      textOverflow
    />
  );
}
```

## Behaviour the types don't state

- **The selected option is matched by its label, not its key.** `withLabel` is true by default,
  and the comparison is `option.label === selectedOption.label`. Two options that read the same
  are both treated as selected; `withLabel={false}` compares keys instead.
- **The option you are on is rendered disabled.** Unless `displaySelectedOption` is set, the
  option matching the selection is greyed out, so re-picking it does nothing. This match uses
  the label even with `withLabel` off.
- **Nothing selects anything.** `onSelect` hands you the option; `selectedOption` is yours to
  update, and the component mirrors whatever you pass back.
- **The list is 200px wide whatever the button is.** `manualWidth` defaults to `"200px"`.
  `scaledOptions` matches it to the button, measured on a later render, so the first open can
  still be 200px.
- **`scaled` is on by default**, so the control fills its parent and `size` has no effect. Turn
  it off to get the 173px of `ComboBoxSize.base`.
- **The keyboard works on the button, and only there.** Enter, Space, ArrowDown and ArrowUp open
  the list. The arrows then move a highlight, Enter or Space picks it, and Escape or Tab closes
  the list.
- The highlight skips separators, disabled options and, unless `displaySelectedOption`, the
  current value. Focus never leaves the button; with `dropDownMaxHeight` the highlighted row
  scrolls into view.
- **`advancedOptions` is walked only when every child is a `DropDownItem`.** A component that
  renders one counts once passed through `markAsDropDownItem`
  (`@onlyoffice/apps-ui-kit/utils/drop-down-item-mark`).
- With any other `advancedOptions` the keys open and close the list but move no highlight. Once
  it is open, Enter, Space, the arrows and typed keys are left to the content.
- Keys pressed inside `children` are left alone too, as clicks there are, unless
  `disableIconClick` is false.
- **`onToggle` hears the keyboard too.** The keys that open and close the list call it with a
  `KeyboardEvent`. A handler that reads `clientX` or `button` has to check which event it got.
- **Loading hides the choice.** `isLoading` draws a spinner in the button. The label, icon,
  `children` and arrow are hidden but keep their space, so the width holds and the value is gone.
- A list of four or more options becomes a bottom sheet on a phone. `hideMobileView` keeps it
  anchored to the button.
- An option's `icon` has to be a component or a URL. The button ignores an element, and fetches a
  URL at runtime through `react-svg`.
- Disabled options are always kept in the list.
- **The component is memoised with a deep comparison of all its props.** A new `options` array on
  every render costs a full walk of it, not a re-render.

## Sub-components

`ComboButton` is the button alone, exported for a control that needs the same shape without a
list of its own. It takes the `selectedOption`, `size`, `type`, `isOpen` and `isLoading` props
described above and calls `onClick`; everything else — opening, choosing, closing — is yours.

| `--combobox-base-width`         | `173px`                                 | Width of the wrapper at `ComboBoxSize.base`                        |
| `--combobox-middle-width`       | `300px`                                 | Width of the wrapper at `ComboBoxSize.middle`                      |
| `--combobox-big-width`          | `350px`                                 | Width of the wrapper at `ComboBoxSize.big`                         |
| `--combobox-huge-width`         | `500px`                                 | Width of the wrapper at `ComboBoxSize.huge`                        |

Set them on the combo box's `style` or on any ancestor.

The four widths apply only with `scaled` off, and they size the wrapper, not the button. The
button keeps its own fixed 173, 300, 350 or 500px, so a larger value widens only the empty area
beside it. Under `noBorder` the button has no border and so no radius.

`--combobox-bg` and `--combobox-open-bg` are read by the stylesheet and paint nothing. The rule
that uses them waits for a `noBorder` class on the wrapper, which the component never sets.

The list is a [`DropDown`](../drop-down/README.md) and takes that component's variables.

## Accessibility

- The button is a `<div role="button">` with `aria-haspopup="listbox"`. `aria-expanded` and
  `aria-pressed` are both true while the list is open, and `aria-disabled` follows `isDisabled`.
- The button is in the tab order unless disabled, and answers the keys described under
  Behaviour.
- The options are `role="option"` rows in a `role="listbox"`. The highlighted option is drawn
  with the list's focus style, and the button names it in `aria-activedescendant`.
- ARIA does not allow `aria-activedescendant` on `role="button"`, so screen readers ignore it and
  the highlight is not announced. A `role="combobox"` with `aria-controls` would carry it; the
  button is not one.
- The control's name comes from its content, the selected option's label. That says the value
  but not what is being chosen.
- **A [`FieldContainer`](../field-container/README.md) caption does not name it.** A `<label>`
  names only native form fields, and this button is a `<div>`.
- **`ariaLabel` replaces the content as the name**, so put the value into it too: "Role of Carol
  Jones: Viewer".
- **A passed `aria-*` lands on the button and is kept.** A passed `aria-label` wins over
  `ariaLabel`. The component sets `aria-expanded`, `aria-pressed`, `aria-haspopup` and
  `aria-activedescendant` over a passed value, and `aria-disabled` while `isDisabled`.
- `title` renders the kit's hover tooltip, which is not an accessible name and needs
  [`RootTooltip`](../tooltip/README.md) mounted.
