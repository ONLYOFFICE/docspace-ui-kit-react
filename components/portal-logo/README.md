# PortalLogo

The portal's white-label logo, fetched from the ONLYOFFICE Apps server and swapped for the theme. It
is the mark at the top of the login and confirmation pages: one `<img>` pointed at the portal's
`logo.ashx`. When that request fails, a bundled logo in the theme's version takes its place.

## Use this when / not when

- Use on a page served by an ONLYOFFICE Apps portal, where `/logo.ashx` resolves and the administrator's
  white-label settings should be honoured.
- Not in your own application — outside a portal the fixed URL fails, and you always get the
  bundled fallback. Render your own `<img>`.
- Not for a room's mark — use [`RoomLogo`](../room-logo/README.md) or
  [`RoomIcon`](../room-icon/README.md).

**Portal-internal.** The source is `/logo.ashx?logotype=…&dark=…&default=false`, an ONLYOFFICE Apps
endpoint. There is no `src` prop, no base-URL prop and no way to point it elsewhere.

## Import

```ts
import { PortalLogo } from "@onlyoffice/apps-ui-kit/components/portal-logo";
```

Also exported from the root barrel `@onlyoffice/apps-ui-kit`.
The component file has a default export, but the folder's `index` re-exports it under a name —
`import PortalLogo from …` does not resolve.

Needs `ThemeProvider` above it in the tree. The theme becomes the `dark` query parameter, so the
request itself differs between themes. Without a provider the context falls back to light and the
dark logo is never requested.

## Minimal example

```tsx
import { PortalLogo } from "@onlyoffice/apps-ui-kit/components/portal-logo";

export function LoginHeader() {
  return <PortalLogo />;
}
```

## Recipes

### The logo that survives small screens

Without `isResizable` the logo is hidden at 600px and narrower. With it, the wrapper becomes a
fixed bar, 48px tall, across the top of the viewport, with the small logo centred in it. The bar
overlays your layout, so the page needs 48px of padding of its own.

```tsx
import { PortalLogo } from "@onlyoffice/apps-ui-kit/components/portal-logo";

export function ConfirmPage({ children }: { children: React.ReactNode }) {
  return (
    <div style={{ paddingTop: 48 }}>
      <PortalLogo isResizable />
      {children}
    </div>
  );
}
```

### Sizing it

The component's own rule sizes the desktop image to 386×44. A width and height set through
`className` must win on specificity. The two desktop variables, set on an ancestor, avoid that.

```tsx
import { PortalLogo } from "@onlyoffice/apps-ui-kit/components/portal-logo";

// In your stylesheet:
//   .login-page { --portal-logo-desktop-img-width: 240px;
//                 --portal-logo-desktop-img-height: 28px; }

export function SmallerLogo() {
  return (
    <div className="login-page">
      <PortalLogo />
    </div>
  );
}
```

## Behaviour the types don't state

- **At 600px and narrower a logo without `isResizable` is `display: none`.** Not smaller —
  gone. This is the single most surprising thing about the component.
- **The width is read once, at first render.** The resize listener is attached only while
  `isResizable` is set, so without it the component's idea of the viewport never changes after
  mount. During server rendering the width starts at `0`, which counts as mobile.
- **A failed request replaces everything.** The whole component, wrapper included, gives way to a
  bundled small logo, so the fixed mobile bar disappears too. `className` still reaches that
  fallback, and `alt` becomes its `aria-label`.
- **An image that failed before hydration is caught too.** When React attaches a complete image
  whose `decode()` rejects, it is swapped the same way.
- **Two separate ideas of "mobile" are in play.** The measured window width decides the layout.
  The user-agent check decides the `not-mobile` class that carries the desktop 386×44 sizing.
  A narrow window on a desktop browser gets both at once.
- **`className` goes on the image, never on the wrapper.** To position or space the logo, target
  the wrapper through a parent of yours.
- **`alt` defaults to the product name as the portal brands it**, `ONLYOFFICE Apps` unbranded. On
  a portal with a name of its own, pass that name through `alt`.

## CSS variables

The component takes no `style`, and `className` lands on the `<img>`, below the element that
reads them. Set each variable on an ancestor of the logo.

| Variable                           | Default           | Effect                                     |
| ---------------------------------- | ----------------- | ------------------------------------------ |
| `--portal-logo-desktop-img-width`  | `386px`           | Width of the image on desktop              |
| `--portal-logo-desktop-img-height` | `44px`            | Height of the image on desktop             |
| `--portal-logo-mobile-img-height`  | `24px`            | Height of the small logo in the mobile bar |
| `--portal-logo-mobile-height`      | `48px`            | Height of that fixed mobile bar            |
| `--portal-logo-mobile-bg`          | the header's grey | Background of that bar                     |

Without `--portal-logo-mobile-bg` the bar takes the portal's `--header-background-color`, then a
grey of its own.

The three mobile variables apply only to the fixed bar: with `isResizable`, at 600px and narrower.
The two desktop ones hang on the `not-mobile` class, which follows the user-agent check, not the
width. A phone browser never reads them, while a narrow desktop window does. There the bar's
image height wins over the desktop one, but `--portal-logo-desktop-img-width` still sizes the logo.

## Accessibility

- The logo is an `<img>` named by `alt`, the product name unless you pass one. On a login page
  where the logo is the only statement of which portal you are on, pass the portal's name.
- The bundled fallback mark, shown when the image fails to load, is an `<svg>` with `role="img"`
  and the same name as `aria-label`. With `alt=""` both the image and the fallback are
  decorative: the image gets an empty `alt`, the mark `aria-hidden`.
- **A passed `aria-*` lands on the image, or on the fallback mark, and is kept.** A passed
  `aria-label` wins over `alt`.
- Nothing here is focusable or interactive; the logo is not a link.
- In the resizable mobile layout the bar is fixed at the top of the viewport, above the page
  content. It can cover a focused element unless the page reserves space.
