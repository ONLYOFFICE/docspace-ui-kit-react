# FilterInput

The bar above a file listing: search, a filter panel, a sort menu, a view switch and the chips for
what is in force. It holds no filter state of its own — you tell it what is selected through two
getters and it tells you what changed.

## Use this when / not when

- **This is portal-internal.** Its filter groups, its contacts pages and its room grouping row are
  the portal's own; the type even names the pages it can be on.
- Use it above a listing that already has a filter model of the shape the panel expects.
- Not for a plain search box — [`SearchInput`](../search-input/README.md) is that, and this renders
  one inside itself.
- Not for the chips alone — [`SelectedItem`](../selected-item/README.md) is the chip.
- **Every getter must be stable.** They are effect dependencies, and one recreated on each render
  either re-runs a request or loops; see the behaviour notes.
- **It renders no selector.** The step where the panel picks a person or a room is yours, through
  `renderSelector`.

## Import

```ts
import FilterInput from "@onlyoffice/apps-ui-kit/components/filter";
```

It is a **default** export, so the name is yours to choose. `FilterInput` is also exported by
name, and reaches the root barrel `@onlyoffice/apps-ui-kit` that way.

Needs `ThemeProvider` above it in the tree for its colours. It also needs `TranslationProvider`
for the labels it does not take as props. Without one, "Clear all", "All rooms", "Create group",
Apply, Cancel and the view switch names render as **empty strings**.

## Minimal example

```tsx
import { useCallback, useState } from "react";

import FilterInput from "@onlyoffice/apps-ui-kit/components/filter";
import { DeviceType } from "@onlyoffice/apps-ui-kit/enums";

export function ListingFilter() {
  const [search, setSearch] = useState("");
  const [clearSearch, setClearSearch] = useState(false);

  const getSelectedInputValue = useCallback(() => search, [search]);
  const getSelectedFilterData = useCallback(() => [], []);
  const getViewSettingsData = useCallback(() => [], []);
  const getFilterData = useCallback(async () => [], []);
  const getSortData = useCallback(() => [], []);
  const getSelectedSortData = useCallback(
    () => ({ sortDirection: "asc" as const, sortId: "AZ" as const }),
    [],
  );

  return (
    <FilterInput
      placeholder="Search"
      onSearch={setSearch}
      onClearFilter={() => setSearch("")}
      clearSearch={clearSearch}
      setClearSearch={setClearSearch}
      getSelectedInputValue={getSelectedInputValue}
      getSelectedFilterData={getSelectedFilterData}
      getViewSettingsData={getViewSettingsData}
      getFilterData={getFilterData}
      getSortData={getSortData}
      getSelectedSortData={getSelectedSortData}
      onFilter={() => {}}
      onSort={() => {}}
      onSortButtonClick={() => {}}
      onChangeViewAs={() => {}}
      removeSelectedItem={() => {}}
      clearAll={() => {}}
      view="files"
      viewAs="row"
      viewSelectorVisible={false}
      filterHeader="Filter"
      selectorLabel="Select"
      filterTitle="Filter"
      sortByTitle="Sort by"
      userId="1"
      currentDeviceType={DeviceType.desktop}
      isIndexing={false}
      isIndexEditingMode={false}
      isRecentFolder={false}
      isRooms={false}
      isContactsPage={false}
      isContactsPeoplePage={false}
      isContactsGroupsPage={false}
      isContactsInsideGroupPage={false}
      isContactsGuestsPage={false}
    />
  );
}
```

## Recipes

### Clear the search box from outside the bar

There is no value prop. To empty the field, raise `clearSearch`. The bar clears it, calls
`onClearFilter` and then `setClearSearch(false)` itself, so the flag is a pulse, not a state.

```tsx
import { useCallback, useState } from "react";

import FilterInput from "@onlyoffice/apps-ui-kit/components/filter";
import { Button } from "@onlyoffice/apps-ui-kit/components/button";
import { DeviceType } from "@onlyoffice/apps-ui-kit/enums";

export function ResettableFilter() {
  const [search, setSearch] = useState("");
  const [clearSearch, setClearSearch] = useState(false);

  const getSelectedInputValue = useCallback(() => search, [search]);
  const empty = useCallback(() => [], []);
  const emptyAsync = useCallback(async () => [], []);
  const getSelectedSortData = useCallback(
    () => ({ sortDirection: "asc" as const, sortId: "AZ" as const }),
    [],
  );

  return (
    <div>
      <FilterInput
        placeholder="Search"
        onSearch={setSearch}
        onClearFilter={() => setSearch("")}
        clearSearch={clearSearch}
        setClearSearch={setClearSearch}
        getSelectedInputValue={getSelectedInputValue}
        getSelectedFilterData={empty}
        getViewSettingsData={empty}
        getFilterData={emptyAsync}
        getSortData={empty}
        getSelectedSortData={getSelectedSortData}
        onFilter={() => {}}
        onSort={() => {}}
        onSortButtonClick={() => {}}
        onChangeViewAs={() => {}}
        removeSelectedItem={() => {}}
        clearAll={() => setSearch("")}
        view="files"
        viewAs="row"
        viewSelectorVisible={false}
        filterHeader="Filter"
        selectorLabel="Select"
        filterTitle="Filter"
        sortByTitle="Sort by"
        userId="1"
        currentDeviceType={DeviceType.desktop}
        isIndexing={false}
        isIndexEditingMode={false}
        isRecentFolder={false}
        isRooms={false}
        isContactsPage={false}
        isContactsPeoplePage={false}
        isContactsGroupsPage={false}
        isContactsInsideGroupPage={false}
        isContactsGuestsPage={false}
      />
      <Button label="Reset" onClick={() => setClearSearch(true)} />
    </div>
  );
}
```

### Show the filters in force as removable chips

The chips come from `getSelectedFilterData`, not from a prop. Removing one calls
`removeSelectedItem`. The bar has already dropped the chip by then, so your model catches up
rather than confirms.

```tsx
import { useCallback, useState } from "react";

import FilterInput from "@onlyoffice/apps-ui-kit/components/filter";
import type { TItem } from "@onlyoffice/apps-ui-kit/components/filter";
import { DeviceType, FilterGroups } from "@onlyoffice/apps-ui-kit/enums";

export function FilterWithChips() {
  const [items, setItems] = useState<TItem[]>([
    { key: "docx", label: "Documents", group: FilterGroups.filterType },
  ]);

  const getSelectedFilterData = useCallback(() => items, [items]);
  const empty = useCallback(() => [], []);
  const emptyAsync = useCallback(async () => [], []);
  const getSelectedSortData = useCallback(
    () => ({ sortDirection: "asc" as const, sortId: "AZ" as const }),
    [],
  );

  return (
    <FilterInput
      placeholder="Search"
      onSearch={() => {}}
      onClearFilter={() => {}}
      clearSearch={false}
      setClearSearch={() => {}}
      getSelectedInputValue={useCallback(() => "", [])}
      getSelectedFilterData={getSelectedFilterData}
      getViewSettingsData={empty}
      getFilterData={emptyAsync}
      getSortData={empty}
      getSelectedSortData={getSelectedSortData}
      onFilter={() => {}}
      onSort={() => {}}
      onSortButtonClick={() => {}}
      onChangeViewAs={() => {}}
      removeSelectedItem={({ key }) =>
        setItems((rest) => rest.filter((item) => item.key !== key))
      }
      clearAll={() => setItems([])}
      view="files"
      viewAs="row"
      viewSelectorVisible={false}
      filterHeader="Filter"
      selectorLabel="Select"
      filterTitle="Filter"
      sortByTitle="Sort by"
      userId="1"
      currentDeviceType={DeviceType.desktop}
      isIndexing={false}
      isIndexEditingMode={false}
      isRecentFolder={false}
      isRooms={false}
      isContactsPage={false}
      isContactsPeoplePage={false}
      isContactsGroupsPage={false}
      isContactsInsideGroupPage={false}
      isContactsGuestsPage={false}
    />
  );
}
```

## Behaviour the types don't state

- **Every getter is an effect dependency, so wrap each in `useCallback`.** `getViewSettingsData` is
  read on every render and again in an effect that sets state.
- An inline `getViewSettingsData` therefore re-renders the bar without end.
  `getSelectedFilterData` re-fetches, and `getSelectedInputValue` is read again, on every new
  function.
- **The search box has no value prop.** It shows what `getSelectedInputValue` returns, reports a
  string, and is cleared by the `clearSearch` pulse.
- **A late answer does not overwrite a newer edit.** The bar remembers the queries sent to
  `onSearch` that you have not reported back.
- When `getSelectedInputValue` returns one the user has since replaced, the field stays as the user
  left it. A repeat of the last value changes nothing either.
- **The filter panel works on a copy.** It opens as a side panel of grouped options, and Apply is
  enabled only once the selection differs.
- Apply hands the whole selection to `onFilter`; Cancel or closing discards it. The clear icon in
  the panel's header is the exception: it calls `onFilter([])` at once when filters were in force.
- **The sort menu marks the current field with an arrow** in the current direction. Picking that
  field again reverses the direction; picking another keeps it.
- `onSortButtonClick` reports each change of the sort menu: `true` as it opens, `false` as it
  closes. The first render reports nothing, and unmounting with the menu open reports `false`.
- **The sort button disappears** with `isIndexing`, `isFlowsPage` or `isRecentFolder`. The filter
  button disappears with `isIndexEditingMode` or `isFlowsPage`.
- **The view selector is in two places.** On a desktop it is one button beside the sort button,
  offering the view you are not in.
- Below the desktop layout it moves inside the sort menu, under the `view` text.
  `viewSelectorVisible` governs both, and `isRecentFolder` keeps the separate button at any width.
- **`viewAs="table"` is treated as `"row"`** by the sort menu and the view selector.
- **The contacts flags shape only the panel's loading skeleton**, and that skeleton shows only with
  `isRooms`. Which groups the panel offers is up to `getFilterData`.
- **The room grouping row needs `withRoomGroups` and `organizeRoomsGrouping`, and no
  `isFilterOrSearchActive`.** A passed `getAllRoomGroups` must settle first, resolved or not.
- Only groups whose `icon` is an object get a chip; a string or `null` icon drops the group. The
  icon's SVG source becomes a data URL.
- **That row measures itself in a hidden copy.** Every chip is drawn twice, once off-screen, and
  the visible row appears once the sizes are in. Chips that do not fit go into a "..." menu.
- **A click anywhere on a filter chip removes it**, not only on its cross. The bar drops the chip
  first and calls `removeSelectedItem` afterwards.
- A failed removal therefore leaves the bar and your model disagreeing until the next read.
- **"Clear all" needs two labelled chips.** The link appears only when more than one selected item
  carries a label.
- **It assigns `window.onscroll`** when the search box is focused on an iOS tablet, replacing any
  handler already there with a no-op.
- **`renderSelector` is not optional in practice.** A selector item opens a step this package
  cannot fill.
- **A group can draw itself.** An item marked `isCustom` is rendered by `renderCustomItem`, which
  gets the group's pending value and `onChange` to set it.
- It also gets `openPanel` and `closePanel` for a nested step that slides in like a selector. The
  step's props are rebuilt on every render, so an open step sees the value it has just set.
- The value is a string key, applied and compared like any other. Anything richer, such as a
  range, is serialized into that key by the host.
- A group holds one value: two custom items in one group share it. A group of the host's own is
  not in `FilterGroups`, so typed code casts its name (`"filter-rating" as FilterGroups`).
- **`hideSearch` removes the field, not the bar's first slot.** The search block stays, holding
  only the main button, so the filter and sort controls keep their place.
- With the field gone nothing calls `onSearch`, and `initSearchValue` and `getSelectedInputValue`
  are shown nowhere.
- **One filter can show as several chips.** A selected item with `chips` draws one chip per entry.
  Removing one calls `removeSelectedItem` with that chip's key and the item's group.
- The bar is a full-width flex column: a 32px row of controls with an 8px margin under it, then the
  chips, then the grouping row.

## Accessibility

- **The filter button is a keyboard button**: `role="button"`, in the tab order, opened with Enter
  or Space. `filterTitle` is its accessible name, and `aria-expanded` follows the panel.
- **The sort button is a combo box button** that Tab reaches, named by `sortByTitle`.
- **The view switch is a keyboard button** named by the translated "switch view" text. Inside the
  sort menu each view icon is one, with `aria-pressed` on the current view.
- **A filter chip is not focusable**, but its cross is a keyboard button named by the translated
  "Remove".
  A room group chip is a keyboard button with `aria-pressed` on the chosen group.
- The grouping row's "..." control is a combo box button named only by its text. The group
  management button is a keyboard button named by its translated tooltip.
- The filter panel is a [`ModalDialog`](../modal-dialog/README.md): `role="dialog"` with
  `aria-modal`, closed by Escape. It is named by `filterHeader`.
- The panel's clear icon is a keyboard button named by the translated "Clear filter".
- **A selector step** replaces the panel's content. Escape goes back from it, and focus returns to
  the item that opened it.
- **A custom item's `openPanel` step** has no such handling: Escape closes the whole panel, and
  focus is not returned.
- The hidden measurement copy of the grouping row is `aria-hidden` and `inert`, so it is neither
  read nor tabbed to.
- The search box is the kit's [`SearchInput`](../search-input/README.md). It takes focus by itself
  whenever the value getter returns a new non-empty value.
- Nothing announces that the listing has been filtered or sorted. The chips are the only report,
  and they are not a live region.
- **A passed `aria-*` lands on the bar's outer element and is kept.** A passed `aria-label` or `aria-labelledby` makes it a `role="group"`, so the name is read.
