# Checkbox

Checkbox with a label, an indeterminate state and an optional help button. It is the control
for a choice the user confirms later, by submitting the form around it.

## Use this when / not when

- Use for one or more independent choices in a form: a list of permissions, a "remember me",
  the select-all of a list.
- Not for a setting that takes effect the moment it is clicked — that reads as a switch, and
  is [`ToggleButton`](../toggle-button/README.md).
- Not for one choice out of several: [`RadioButtonGroup`](../radio-button-group/README.md).
- Not to give the choice a field label and an error message — wrap it in
  [`FieldContainer`](../field-container/README.md), which this component's `hasError` expects.

## Import

```ts
import { Checkbox } from "@onlyoffice/apps-ui-kit/components/checkbox";
```

Also exported from the root barrel `@onlyoffice/apps-ui-kit`.

Needs `ThemeProvider` from `@onlyoffice/apps-ui-kit/providers/theme` above it in the tree.
Without it the box renders in the light palette and ignores the dark theme.

## Minimal example

```tsx
import { useState } from "react";
import { Checkbox } from "@onlyoffice/apps-ui-kit/components/checkbox";

export function TermsCheckbox() {
  const [accepted, setAccepted] = useState(false);

  return (
    <Checkbox
      label="I accept the terms"
      isChecked={accepted}
      onChange={(e) => setAccepted(e.target.checked)}
    />
  );
}
```

## Recipes

### Show a choice the user cannot change

```tsx
import { Checkbox } from "@onlyoffice/apps-ui-kit/components/checkbox";

export function ManagedSetting({ enabled }: { enabled: boolean }) {
  return (
    <Checkbox
      label="Managed by your administrator"
      isChecked={enabled}
      isDisabled
    />
  );
}
```

### Put the caption apart from the box

Use `inputId` when the caption cannot be the `label` prop, because it needs its own
typography or sits elsewhere in the row. A click on the caption then toggles the box, and the
caption names it for assistive technology.

```tsx
import { Checkbox } from "@onlyoffice/apps-ui-kit/components/checkbox";

export function InviteViaContacts({
  enabled,
  onChange,
}: {
  enabled: boolean;
  onChange: (on: boolean) => void;
}) {
  return (
    <div style={{ display: "flex", alignItems: "center", gap: 8 }}>
      <Checkbox
        inputId="invite-contacts-checkbox"
        isChecked={enabled}
        onChange={(e) => onChange(e.target.checked)}
      />
      <label
        htmlFor="invite-contacts-checkbox"
        style={{ cursor: "pointer", fontWeight: 600 }}
      >
        Invite via Contacts
      </label>
    </div>
  );
}
```

### Add a select-all checkbox for a partly selected list

```tsx
import { useState } from "react";
import { Checkbox } from "@onlyoffice/apps-ui-kit/components/checkbox";

const ROOMS = ["Design", "Development", "Marketing"];

export function RoomPicker() {
  const [selected, setSelected] = useState<string[]>([]);

  const toggle = (room: string, on: boolean) =>
    setSelected((current) =>
      on ? [...current, room] : current.filter((item) => item !== room),
    );

  return (
    <div style={{ display: "flex", flexDirection: "column", gap: 8 }}>
      <Checkbox
        label="All rooms"
        isChecked={selected.length === ROOMS.length}
        isIndeterminate={selected.length > 0 && selected.length < ROOMS.length}
        onChange={(e) => setSelected(e.target.checked ? [...ROOMS] : [])}
      />
      {ROOMS.map((room) => (
        <Checkbox
          key={room}
          label={room}
          isChecked={selected.includes(room)}
          onChange={(e) => toggle(room, e.target.checked)}
        />
      ))}
    </div>
  );
}
```

## Behaviour the types don't state

- **It is not a controlled component.** It keeps its own `checked` state, seeded from
  `isChecked` and reset whenever that prop changes. A click flips the box at once, whatever
  your handler decides.
- Passing the same `isChecked` back does not undo a click; only a different value resets the box.
- **The focusable element is the input.** The `<input>` is only visually hidden, and `tabIndex`
  goes on it. The box icon beside it is decorative, `aria-hidden` and no tab stop.
- **`inputId` is the one id that reaches the input.** `id` does not: it goes to the wrapping
  `<label>`, so a `<label htmlFor={id}>` points at another label and does nothing.
- **The change event does not bubble.** The component calls `stopPropagation()`, so a form
  listening for `change` at its root never sees it. Read the state through `onChange`.
- **`isIndeterminate` decides the picture over `isChecked`.** The inner square stays drawn
  after a click, until the prop changes. The click itself clears the input's native
  `indeterminate` flag.
- The label wraps by default. `truncate` holds it on one line with an ellipsis instead.
- `helpButton` renders after the label, and a click on it is swallowed: the checkbox does not
  toggle.
- `title` is read by the `<label>` around the whole control. The shared tooltip opens when the
  pointer rests on the box or the label, once `RootTooltip` is mounted.
- Anything else you pass is spread onto the input element, not onto the label.

## CSS variables

| Variable                      | Default     | Effect                                                            |
| ----------------------------- | ----------- | ----------------------------------------------------------------- |
| `--checkbox-gap`              | `12px`      | Space between the box and the label                               |
| `--checkbox-lh`               | `16px`      | Line height of the row; the label text keeps its own 16px line    |
| `--checkbox-fill-color`       | theme-based | Fill of a checked box, and of an indeterminate box's outer square |
| `--checkbox-border-color`     | theme-based | Border of the box; hover, focus, error and disabled draw over it  |
| `--checkbox-arrow-color`      | theme-based | Colour of the tick in a checked box                               |
| `--checkbox-focus-ring-color` | accent      | The ring around a keyboard-focused box                            |

Set these on the checkbox's `style` or on any ancestor. A disabled box ignores the three colour
settings and draws its own disabled colours.

The other colour variables (`--checkbox-fill-color-default`, `--checkbox-error-color` and the
rest) are **not** consumer settings. The stylesheet assigns them on the component's own element,
so a value set on an ancestor loses. Theme them through the theme provider instead.

## Accessibility

- The control is a real `<input type="checkbox">` inside a `<label>`. A click on the label
  toggles it, and a screen reader announces the label and the state.
- Keyboard focus lands on the input itself. The focused box draws its border in the focus colour,
  with an accent ring around it.
- The keys are the native checkbox's: Space toggles it once however long it is held, and Enter
  does nothing. `onChange` gets the same event a pointer produces.
- The focus stays on the checkbox when it toggles, so the next Tab moves on from it.
- `isDisabled` sets the native `disabled` on the input, which is announced as unavailable.
- `isIndeterminate` sets the input's DOM `indeterminate` property, so the mixed state is
  announced, not merely drawn.
- **A passed `aria-*` is kept.** It is spread onto the input, and the component sets none of
  its own there.
- Without `label` the control has no accessible name. Pass `aria-label`, which reaches the
  input, or point a `<label htmlFor={inputId}>` elsewhere on the page at it.
