# ContextMenu

Menu opened at the pointer through a ref, with submenus, a mobile sheet form and working
keyboard navigation. It has no visibility prop: you keep a ref and call `show(event)`.

## Use this when / not when

- Use for a right-click menu, or the actions of a row, a card or a file: the menu belongs to what
  the user pointed at.
- Use it when the menu has to be reachable from the keyboard. It is the only menu in the kit
  with arrow keys, Enter and Escape that work.
- Not for a menu anchored to a button you control: [`DropDown`](../drop-down/README.md) is
  simpler, and [`ContextMenuButton`](../context-menu-button/README.md) wires the two together.
- Not for choosing a value — [`ComboBox`](../combobox/README.md).
- Not as a dialog. The backdrop only appears in the mobile form or with `ignoreChangeView`,
  and nothing traps focus.

## Import

```ts
import { ContextMenu } from "@onlyoffice/apps-ui-kit/components/context-menu";
```

Also exported from the root barrel `@onlyoffice/apps-ui-kit`.

Needs `ThemeProvider` from `@onlyoffice/apps-ui-kit/providers/theme`, and
`TranslationProvider` from `@onlyoffice/apps-ui-kit/providers/translation` for the labels the
menu supplies itself on the mobile sheet.

## Minimal example

The menu is opened by handing an event to `show`, which is where its position comes from.

```tsx
import { useRef } from "react";
import {
  ContextMenu,
  type ContextMenuRefType,
} from "@onlyoffice/apps-ui-kit/components/context-menu";

export function FileCard({
  name,
  onRename,
}: {
  name: string;
  onRename: () => void;
}) {
  const menu = useRef<ContextMenuRefType>(null);

  return (
    <div onContextMenu={(event) => menu.current?.show(event)}>
      {name}
      <ContextMenu
        ref={menu}
        model={[{ key: "rename", label: "Rename", onClick: onRename }]}
      />
    </div>
  );
}
```

## Recipes

### Items that depend on the selection

`getContextModel` is called each time the menu opens, so it sees the current state; `model` is
only the fallback.

```tsx
import { useRef, useState } from "react";
import {
  ContextMenu,
  type ContextMenuRefType,
} from "@onlyoffice/apps-ui-kit/components/context-menu";

export function SelectableCard({ name }: { name: string }) {
  const menu = useRef<ContextMenuRefType>(null);
  const [pinned, setPinned] = useState(false);

  return (
    <div onContextMenu={(event) => menu.current?.show(event)}>
      {name}
      <ContextMenu
        ref={menu}
        model={[]}
        getContextModel={() => [
          {
            key: "pin",
            label: pinned ? "Unpin" : "Pin",
            onClick: () => setPinned(!pinned),
          },
          { key: "sep", isSeparator: true },
          { key: "delete", label: "Delete", disabled: pinned },
        ]}
        onHide={() => {}}
      />
    </div>
  );
}
```

### A submenu, anchored to a button rather than the pointer

```tsx
import { useRef } from "react";
import {
  ContextMenu,
  type ContextMenuRefType,
} from "@onlyoffice/apps-ui-kit/components/context-menu";

export function ShareMenu({ onCopy }: { onCopy: () => void }) {
  const menu = useRef<ContextMenuRefType>(null);
  const anchor = useRef<HTMLDivElement>(null);

  return (
    <div ref={anchor}>
      <button type="button" onClick={(event) => menu.current?.toggle(event)}>
        Share
      </button>
      <ContextMenu
        ref={menu}
        containerRef={anchor}
        scaled
        model={[
          { key: "copy", label: "Copy the link", onClick: onCopy },
          {
            key: "access",
            label: "Access",
            items: [
              { key: "view", label: "Can view" },
              { key: "edit", label: "Can edit" },
            ],
          },
        ]}
      />
    </div>
  );
}
```

## Behaviour the types don't state

- **It is opened imperatively, and the event is not optional.** `show(event)` places the menu at
  the event's `pageX` and `pageY`, and calls `preventDefault` and `stopPropagation`.
- The menu flips when it would run past the viewport. With `containerRef` it opens under that
  element instead, and the offsets are subtracted from its left edge.
- **`getContextModel` replaces `model` on every open**, so it sees the state of that moment.
  `model` is read on every render instead, which suits a fixed list.
- **A leading or trailing separator is dropped** from what `getContextModel` returns, so a
  filtered list does not end in a rule. A `model` is drawn as given.
- **On a phone the menu becomes a sheet at the bottom.** That happens at 600px wide or less, when
  the menu is taller than 210px or `ignoreChangeView` is set.
- The sheet is portalled into `#root`, found by that literal id, and only then does the backdrop
  appear. On a desktop `withBackdrop` shows nothing unless `ignoreChangeView` is set too.
- **On the sheet a submenu replaces the list in place**, rather than opening to the side. A back
  button named by the translated "Back" sits in its header.
- **Disabled items are dropped from the list** unless `showDisabledItems` is set. Then they show
  greyed out, and `getTooltipContent` explains on hover why.
- **Escape, the arrow keys and Enter work** while the menu is open, through a `keyup` listener
  on the window. `withHotkeys={false}` turns them off. Nothing else in the kit's menus does
  this.
- Opening the menu again while it is open re-shows it at the new position rather than toggling
  it; `toggle(event)` is the one that closes.
- An item with `items` opens a submenu to the side on hover, to any depth. One with `onLoad`
  fetches its items the first time it opens.
- **A string `icon` is inlined only when the page may fetch it itself.** An SVG data URL or a
  same-origin `.svg` goes through `react-svg` and takes the text colour.
- Anything else — a cross-origin `.svg`, a bitmap, a plugin's asset — is an `<img>`, so it needs
  no CORS headers. The mobile sheet draws a data URL as an `<img>` too.
- An item's `template` replaces its link on the desktop list; the mobile sheet ignores it.
- `global` opens the menu on a right-click anywhere in the document, with no `show` call of
  yours.
- `autoZIndex`, on by default, sets the menu's stacking order on each open: `baseZIndex` plus a
  counter the kit shares, from 1001.

## CSS variables

The menu is portalled out of its parent, so a variable set on a wrapper never reaches it. Pass
them through the menu's own `style`, set them on the theme provider, or render the menu inside
the wrapper with `appendTo`. Every default not given below comes from the theme.

## Accessibility

- Each item is a link with `role="menuitem"` and each divider has `role="separator"`, but the
  menu container has no `menu` role.
- The keyboard works: Arrow Up and Down move the highlight, and Arrow Right and Left enter and
  leave a submenu. Enter chooses the item or opens its submenu, and Escape closes.
- Focus is not moved into the menu and not trapped. The highlight is only drawn, so a screen
  reader does not announce which item it is on.
- Nothing links the opener to the menu by `aria-controls` or `aria-expanded`; add those on your
  own control.
- **A passed `aria-*` lands on the menu panel and is kept**, the element that takes `id`. A
  passed name makes the panel a `role="group"`, not a `menu`; point `aria-controls` at its `id`.
- A right-click is the usual way in, which no keyboard user has. Give the same actions a button
  as well, as [`Row`](../rows/row/README.md) does.
