# Selector

Panel for picking one or many things out of a list too long to render at once. It is the
portal's people picker, room picker and "save as" browser, and it brings its own search,
breadcrumbs, pagination and footer.

## Use this when / not when

- Use to pick people, groups, rooms, folders or files from a list fetched a page at a time. It
  virtualises the rows and asks for each next page.
- Not for a short, fixed list of options — [`ComboBox`](../combobox/README.md) is that, without
  the pagination.
- Not for a table of data with columns — [`Table`](../table/README.md) is that.
- Not as a dialog on its own: it fills whatever box it is in. `useAside` turns it into a panel;
  otherwise wrap it in [`ModalDialog`](../modal-dialog/README.md).

## Import

```ts
import { Selector } from "@onlyoffice/apps-ui-kit/components/selector";
```

Also exported from the root barrel `@onlyoffice/apps-ui-kit`.

The folder also exports the three skeletons its own props ask for — `RowLoader`,
`SearchLoader`, `BreadCrumbsLoader` — and every type on this page.

Needs `ThemeProvider` from `@onlyoffice/apps-ui-kit/providers/theme`. Needs `TranslationProvider`
from `@onlyoffice/apps-ui-kit/providers/translation` for the strings Selector prints itself. Those
are the user-type labels and the empty screen's "Back" and "Clear filter" links.

## Minimal example

The six empty-screen fields and the four pagination props are required even without pagination.
The smallest working Selector is still a dozen props.

```tsx
import { useCallback, useState } from "react";
import {
  RowLoader,
  Selector,
  type TSelectorItem,
} from "@onlyoffice/apps-ui-kit/components/selector";

export function PickOnePerson({ people }: { people: TSelectorItem[] }) {
  const [chosen, setChosen] = useState<TSelectorItem | null>(null);

  const loadNextPage = useCallback(async () => {}, []);

  return (
    <div style={{ width: 480, height: 485 }}>
      <Selector
        items={people}
        totalItems={people.length}
        hasNextPage={false}
        isNextPageLoading={false}
        isLoading={false}
        disableFirstFetch
        loadNextPage={loadNextPage}
        rowLoader={<RowLoader isContainer />}
        isMultiSelect={false}
        selectedItem={chosen}
        onSelect={(item) => setChosen(item)}
        submitButtonLabel="Add"
        disableSubmitButton={false}
        onSubmit={(selected) => {
          console.log(selected);
        }}
        emptyScreenImage=""
        emptyScreenHeader="Nobody here yet"
        emptyScreenDescription="Invite somebody and they will show up in this list."
        searchEmptyScreenImage=""
        searchEmptyScreenHeader="Nothing matches"
        searchEmptyScreenDescription="Try a shorter query."
      />
    </div>
  );
}
```

"a search box needs somewhere to send the query".

### `TSelectorItem`

One entry of `items`. The type requires only `label`, but a row without an `id` is drawn as
`rowLoader`. The rest depend on what the row stands for: a person carries `email` and `status`,
a room `roomType` and `shared`. `isCreateNewItem` and `isInputItem` make the create link and the
inline name field.

## Recipes

### Show a loader while the list loads

`isLoading` replaces the body with `rowLoader` on the first fetch. `isContentLoading` leaves the
rows in place and dims them, for a search or a folder change. It wins when both are set.

```tsx
import { useCallback, useState } from "react";
import {
  RowLoader,
  SearchLoader,
  Selector,
  type TSelectorItem,
} from "@onlyoffice/apps-ui-kit/components/selector";

export function SearchablePeople({
  fetchPage,
}: {
  fetchPage: (query: string) => Promise<TSelectorItem[]>;
}) {
  const [items, setItems] = useState<TSelectorItem[]>([]);
  const [query, setQuery] = useState("");
  const [isFirstLoad, setIsFirstLoad] = useState(true);
  const [isRefreshing, setIsRefreshing] = useState(false);

  const run = useCallback(
    async (next: string, first: boolean) => {
      if (first) setIsFirstLoad(true);
      else setIsRefreshing(true);

      setItems(await fetchPage(next));
      setIsFirstLoad(false);
      setIsRefreshing(false);
    },
    [fetchPage],
  );

  const loadNextPage = useCallback(async () => {
    await run(query, true);
  }, [query, run]);

  return (
    <div style={{ width: 480, height: 485 }}>
      <Selector
        items={items}
        totalItems={items.length}
        hasNextPage={false}
        isNextPageLoading={false}
        isLoading={isFirstLoad}
        isContentLoading={isRefreshing}
        loadNextPage={loadNextPage}
        rowLoader={<RowLoader isContainer />}
        withSearch
        searchLoader={<SearchLoader />}
        isSearchLoading={false}
        searchValue={query}
        searchPlaceholder="Search"
        onSearch={(value, entered) => {
          setQuery(value);
          entered?.();
          void run(value, false);
        }}
        onClearSearch={(left) => {
          setQuery("");
          left?.();
          void run("", false);
        }}
        isMultiSelect={false}
        submitButtonLabel="Add"
        disableSubmitButton={false}
        onSubmit={(selected) => {
          console.log(selected);
        }}
        emptyScreenImage=""
        emptyScreenHeader="Nobody here yet"
        emptyScreenDescription="Invite somebody and they will show up in this list."
        searchEmptyScreenImage=""
        searchEmptyScreenHeader="Nothing matches"
        searchEmptyScreenDescription="Try a shorter query."
      />
    </div>
  );
}
```

### Build a "Save as" dialog with a folder trail and a file name

`withBreadCrumbs` draws the trail above the list and `withFooterInput` puts a name field in the

```tsx
import { useCallback, useState } from "react";

  RowLoader,
  Selector,

  trail,
  openFolder,

  folders: TSelectorItem[];
  trail: TBreadCrumb[];
  openFolder: (crumb: TBreadCrumb) => void;
  save: (folder: TSelectorItem | undefined, name: string) => void;

  const [folder, setFolder] = useState<TSelectorItem | null>(null);
  const loadNextPage = useCallback(async () => {}, []);

        footerInputHeader="File name"

        items={folders}

        isLoading={false}

        loadNextPage={loadNextPage}
        rowLoader={<RowLoader isContainer />}
```

## Behaviour the types don't state

- **It needs a parent with a real height.** The body measures itself and sizes the virtual list
  from that. In a box of automatic height the list is zero tall, under the header and footer.
- `isSSR` is the escape hatch: it renders every row as plain markup until a height is measured.
- **The list height is arithmetic, not layout.** Fixed heights are subtracted from the measured
  body: search 44px, tabs 33px, breadcrumbs 38px, "select all" 61px, `descriptionText` 32px.
- The footer counts as 73px, 110px with the checkbox, 145px with the input and 181px with both.
  With both, an input in error adds 20px.
- Only the `withInfo` note, the info bar and `injectedElement` are measured. Restyle any other
  part to a different height and the list does not follow.
- **Selection is seeded, not controlled.** `selectedItems`, `selectedItem`, `isChecked` and
  `currentFooterInputValue` are copied into Selector's own state, so later changes do not move
  the ticks.
- The current values come back through `onSubmit`, never through a change handler.
- **It fetches on mount.** `loadNextPage(0)` runs on the first render unless
  `disableFirstFetch` is set, even when `items` already holds a page.
- **Escape and Enter are bound to the window**, not to the panel. Escape calls `onCancel`, and an
  Enter keyup submits from anywhere on the page.
- Enter is left alone on a button or the search box, and while the submit button is disabled.
  Both keys stand down while the inline name row is open.
- Both also stand down while a modal dialog opened after the selector is on screen. Two Selectors
  on one page both answer the same key.
- **The search callback is what shows the search empty screen.** `onSearch` gets the trimmed
  query and a callback. Until you call it, a query that matches nothing shows the _folder_ empty
  screen.
- A query that trims to nothing goes to `onClearSearch` instead.
- **The back arrow is drawn only for `withoutBackButton: false`.** Leaving the prop out hides
  it, exactly as `true` does.
- **Rows are 48px, always.** A separator row is 16px, or 25px with `isSectionSeparator`.
  Nothing measures a row's content.
- **Two rows have fixed positions.** The `isCreateNewItem` row must be first in `items`, and the
  `isInputItem` row second.
- The inline name field takes over the whole body while it is there. The empty screen turns the
  create row into its link.
- **`maxSelectedItems` fails silently without `onSelectLimitReached`.** Past the limit the
  unticked rows go grey and stop responding, with no message.
- With `onSelectLimitReached` the rows stay active, and you are told of each tick past the limit.
- **A row with `isSystem` is sorted to the top**, and a divider goes in under the first row.
- The strings Selector prints itself come from the app's i18n instance, not from props. They are
  the user-type labels, "Back", "Clear filter" and "contains special characters".

## Accessibility

- **The list is one Tab stop, a listbox.** Its scroll container takes the focus and is named by the
  header's title.
- It names the row the keyboard is on with `aria-activedescendant`. Rows are options with
  `aria-selected`; separators and loading rows are `role="presentation"`.
- Focused, the list puts the keyboard on the selected row on screen, or else on the first row.
- The arrows, Home and End move between the rows that can be picked, and scroll to them. They skip
  separators, the new-name field, disabled rows and rows the selection limit disables.
- Enter or Space click the row, as the pointer would: open a folder, pick an item, start "New
  folder". The Enter that opened a row does not also submit the selector.
- Enter on the row already picked in single select submits the choice instead of unpicking it.
- Picking a row keeps the keyboard on it. Only a new list, from an opened folder or a search,
  starts again from its first row.
- The row is ringed only while the focus came from the keyboard. Its own controls, the
  multi-select checkbox and the "New" row's button, are not Tab stops.
- A "New" row with a menu opens it with Enter, and the focus moves to its first entry. The arrows
  walk it and Enter or Space picks one.
- Escape or Tab closes that menu and gives the focus back to the list.
- With `isSSR`, which renders the rows without the virtual list, none of this applies.
- **Focus moves into the selector when it mounts**, to the list unless the search box already has
  it. The new-name field takes the focus when it appears, with its text selected.
- Neither move scrolls the page (`preventScroll`), so a selector further down does not pull the
  page to itself.
- From there Tab moves on in document order. In a side panel it cycles through the header, the
  search box, the list and the footer ([`Aside`](../aside/README.md)'s focus trap).
- Escape and Enter are listened for on the window, so they act with focus outside the panel.
  Enter submits without the button being focused.
- The empty screen's create, back and clear-filter controls are buttons to the keyboard
  (`role="button"`, Enter and Space), named by their labels.
- A breadcrumb before the last is a link to the keyboard (Enter); the last one, where the list
  is, carries `aria-current="page"`.
- The footer's submit and cancel buttons are native buttons, reached with Tab and pressed with
  Enter or Space.
- Give the panel a name yourself: `headerProps.headerLabel` renders as text, not as a label for
  the region.
- **A passed `aria-*` lands on the outer element and is kept.** It has no role, so a name there is not
  read.
