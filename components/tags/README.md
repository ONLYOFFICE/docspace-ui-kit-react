# Tags

One row of tags that keeps to its width, collapsing the rest into an overflow tag. It is what a
room row and a room card use to show their tags on a single line.

## Use this when / not when

- Use for the tags of one object, on one line, where the row's width is fixed and the extras
  have to go somewhere.
- Not for a single tag — [`Tag`](../tag/README.md) on its own is smaller and lets you set its
  width yourself.
- Not for a wrapping cloud of tags; this row is `overflow: hidden` and never wraps. Lay
  [`Tag`](../tag/README.md)s out in your own flex container for that.
- Not for the user's own picks, which should be removable — that is
  [`SelectedItem`](../selected-item/README.md).

## Import

```ts
import { Tags } from "@onlyoffice/apps-ui-kit/components/tags";
```

Also exported from the root barrel `@onlyoffice/apps-ui-kit`.

Needs `ThemeProvider` from `@onlyoffice/apps-ui-kit/providers/theme`, which the tags and the
overflow menu both read their colours from.

## Minimal example

`columnCount` is how many tags are drawn before the rest collapse; it is required.

```tsx
import { Tags } from "@onlyoffice/apps-ui-kit/components/tags";

export function RoomTags({ tags }: { tags: string[] }) {
  return (
    <div style={{ width: 320 }}>
      <Tags
        tags={tags}
        columnCount={3}
        onSelectTag={(tag) => console.log(tag.label)}
      />
    </div>
  );
}
```

## Recipes

### All tags, no collapsing

`columnCount={-1}` draws every tag at a 195px cap and never builds an overflow tag. The row
still does not wrap, so anything past its width is clipped.

```tsx
import { Tags } from "@onlyoffice/apps-ui-kit/components/tags";

export function AllRoomTags({ tags }: { tags: string[] }) {
  return (
    <Tags
      tags={tags}
      columnCount={-1}
      onSelectTag={(tag) => alert(tag.label)}
    />
  );
}
```

### Open your own menu from the overflow tag

`onOptionTagClick` replaces the built-in drop-down. The overflow tag is then labelled `+N`, and a
click on it calls you with `"overflow"`; `optionTagRef` points at the element to anchor to. The
plus tag of `showCreateTag` calls the same handler with `"create"`.

```tsx
import { useRef, useState } from "react";
import { Tags } from "@onlyoffice/apps-ui-kit/components/tags";
import { DropDown } from "@onlyoffice/apps-ui-kit/components/drop-down";
import { DropDownItem } from "@onlyoffice/apps-ui-kit/components/drop-down-item";

export function RoomTagsWithMenu({ tags }: { tags: string[] }) {
  const anchor = useRef<HTMLDivElement | null>(null);
  const [open, setOpen] = useState(false);

  return (
    <div style={{ width: 280 }}>
      <Tags
        tags={tags}
        columnCount={2}
        optionTagRef={anchor}
        onOptionTagClick={(kind) => kind === "overflow" && setOpen(true)}
        onSelectTag={(tag) => console.log(tag.label)}
      />
      <DropDown
        open={open}
        forwardedRef={anchor}
        clickOutsideAction={() => setOpen(false)}
      >
        {tags.slice(2).map((tag) => (
          <DropDownItem key={tag} label={tag} onClick={() => setOpen(false)} />
        ))}
      </DropDown>
    </div>
  );
}
```

## Behaviour the types don't state

- **The row's width is shared out among the visible tags.** Each gets an equal share of the
  measured width, less room for the overflow or create tag. A long label truncates with an
  ellipsis instead of widening the row.
- **The widths are measured again whenever the row is resized**, as well as on a change of
  `tags`, `columnCount`, `showCreateTag` or `onOptionTagClick`. A `ResizeObserver` watches the
  row; where the environment has none, the widths stay at the last measurement.
- **`columnCount` is a count of tags, not of pixels.** `-1` draws them all, and `0` collapses
  them all into the overflow tag. Anything below `tags.length` adds the overflow tag after that
  many tags.
- **The overflow tag looks different depending on whether you handle it.** Without
  `onOptionTagClick` it is labelled `...` and opens a [`DropDown`](../drop-down/README.md) of the
  hidden labels. With it, the label becomes `+N` and the menu is yours to render.
- **The plus tag of `showCreateTag` survives an overflow.** When everything fits it comes after
  the tags, or before them under `columnCount={-1}`.
- When the tags overflow, the plus tag comes after the overflow tag, and the visible tags share
  what is left of the row.
- **The create tag and the overflow tag share `onOptionTagClick`**, which is told which one was
  clicked: `"overflow"` or `"create"` (`TOptionTagKind`). `optionTagRef` points at the overflow
  tag when there is one, and at the create tag only when there is not.
- **A tag with its own `TagType.onClick` calls that instead of `onSelectTag`**, with no
  arguments. Every other tag, and every entry of the built-in menu, reports through `onSelectTag`.
- An entry of the built-in menu whose hidden tag has an `onClick` calls that, matched by label.
- **Tags with the same text do not collide on the React key**, built from the key or label and
  the position. Their `data-testid` is `tag_item_<label>`, the same for both.
- **A `TagType` marked `isThirdParty` is fixed at 44px and its label is not rendered** — only
  its icon is, so such a tag must carry one.
- **`maxWidth` on a `TagType` is overwritten**, always, by the width the row computes.
- **The row is `display: flex`, `width: 100%` and `overflow: hidden`.** It takes the width of
  its parent and clips, so the parent is what decides how much fits.
- `removeTagIcon` does not remove anything: it drops the leading margin of each entry in the
  built-in overflow menu.
- `TagsProps` is not exported from the folder's entry point — type a wrapper's props with
  `React.ComponentProps<typeof Tags>`.

## CSS variables

The row itself has one; the tags inside follow [`Tag`](../tag/README.md#css-variables).

| Variable                      | Default | Effect                                           |
| ----------------------------- | ------- | ------------------------------------------------ |
| `--tags-overflow-text-margin` | `8px`   | Leading margin of an entry in the overflow menu. |

The overflow menu is portalled to the document body, so set this variable on `:root` or `body`.
A wrapper or the `style` prop never reaches it. `removeTagIcon` drops the margin altogether.

## Accessibility

- The row is a `<div role="group">` named by `ariaLabel`, which defaults to the translated
  `Common:Tags` ("Tags").
- **Every tag in the row is a button on the tab order**, the overflow and create tags included.
  The row gives each `role="button"` and `tabindex="0"`, and turns Enter and Space into a click.
- A disabled tag gets no `tabindex`.
- Each tag's label is its accessible name (`aria-label`), and a disabled tag carries
  `aria-disabled`. The create tag has no text, so it is named by `createTagLabel`, the
  translated "Add" by default.
- The built-in overflow tag carries `aria-haspopup="listbox"` and `aria-expanded`. Opened from
  the keyboard, it moves the focus to the first entry.
- In the menu, Up and Down move between entries, and Enter or Space selects one and returns the
  focus to the overflow tag. Escape does the same without selecting; Tab closes it and moves on.
- **The row has no list semantics.** The tags are not `<li>`s, so a screen reader reads a run of
  labels with no sense of how many there are.
- **A passed `aria-*` lands on the group and is kept.** A passed `aria-label` wins over
  `ariaLabel`.
- The overflow menu is a [`DropDown`](../drop-down/README.md) and inherits its behaviour,
  including closing on an outside click.
