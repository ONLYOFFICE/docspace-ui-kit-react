# Navigation

The file manager's header: breadcrumb title, back arrow, and the row of buttons that acts on the
current folder. It is built for the ONLYOFFICE Apps document browser. It expects a folder trail,
two context menu getters and the device type.

## Use this when / not when

- **This is portal-internal.** It ships for the ONLYOFFICE Apps client, and outside that layout
  most of its props have no natural source.
- Use it when you are rebuilding a file browser with the same trail-and-actions header and can
  supply a `Section` around it.
- Not for an application's own navigation bar — that is [`NavMenu`](../nav-menu/README.md), or
  [`Tabs`](../tabs/README.md) for switching views.
- **It is not responsive by itself.** The `currentDeviceType` you pass decides which buttons
  appear, so a wrong value shows the wrong header.

## Import

```ts
import Navigation from "@onlyoffice/apps-ui-kit/components/navigation";
```

It is a **default** export, so the name is yours to choose. The root barrel carries it as
`Navigation` too. Prefer the subpath: the barrel does not build without four optional peers, see
[Which import form](../../docs/getting-started.md#which-import-form).

Needs `ThemeProvider` above it in the tree. Every colour it uses is declared only under that
provider's `light` and `dark` classes, and the mirrored arrows come from its `rtl` class.

It also reads the enclosing [`Section`](../section/README.md)'s context for the height the drop
box may use. Without one the drop box takes the height of its own rows.

## Minimal example

```tsx
import { useState } from "react";

import Navigation from "@onlyoffice/apps-ui-kit/components/navigation";
import { DeviceType } from "@onlyoffice/apps-ui-kit/enums";

const trail = [
  { id: "1", title: "Documents", isRootRoom: true },
  { id: "2", title: "Contracts", isRootRoom: false },
];

export function FolderHeader() {
  const [infoPanel, setInfoPanel] = useState(false);

  return (
    <Navigation
      title="Contracts"
      navigationItems={trail}
      isRootFolder={false}
      currentDeviceType={DeviceType.desktop}
      isDesktop
      showTitle
      withLogo={false}
      burgerLogo=""
      titleIcon=""
      rootRoomTitle="Documents"
      showRootFolderTitle
      showNavigationButton={false}
      canCreate
      isPlusButtonVisible
      isContextButtonVisible
      getContextOptionsPlus={() => [{ key: "folder", label: "New folder" }]}
      getContextOptionsFolder={() => [{ key: "rename", label: "Rename" }]}
      onClickFolder={(id) => console.info(id)}
      onBackToParentFolder={() => console.info("back")}
      isInfoPanelVisible={infoPanel}
      toggleInfoPanel={() => setInfoPanel((value) => !value)}
    />
  );
}
```

## Recipes

### Making the buttons appear

`canCreate` is not enough. The plus and folder buttons each need a second flag that has no
default. A header given only the getters renders neither of them.

```tsx
import Navigation from "@onlyoffice/apps-ui-kit/components/navigation";
import { DeviceType } from "@onlyoffice/apps-ui-kit/enums";

export function HeaderWithActions({ canCreate }: { canCreate: boolean }) {
  return (
    <Navigation
      title="Contracts"
      navigationItems={[{ id: "1", title: "Contracts", isRootRoom: true }]}
      isRootFolder
      currentDeviceType={DeviceType.desktop}
      isDesktop
      showTitle
      withLogo={false}
      burgerLogo=""
      titleIcon=""
      rootRoomTitle=""
      showRootFolderTitle={false}
      showNavigationButton={false}
      canCreate={canCreate}
      isPlusButtonVisible={canCreate}
      isContextButtonVisible
      getContextOptionsPlus={() => [{ key: "folder", label: "New folder" }]}
      getContextOptionsFolder={() => [{ key: "rename", label: "Rename" }]}
      onClickFolder={() => {}}
      onBackToParentFolder={() => {}}
      isInfoPanelVisible={false}
      toggleInfoPanel={() => {}}
      titles={{ actions: "Actions", infoPanel: "Info panel" }}
    />
  );
}
```

### The breadcrumb drop box

The trail is not rendered inline. Clicking the folder name opens a list of every entry in
`navigationItems`, and choosing one calls `onClickFolder`. There is no prop for the box: it is
internal state. It does not open in the root folder or with an empty trail. A click outside or
Escape closes it.

```tsx
import { useState } from "react";

import Navigation from "@onlyoffice/apps-ui-kit/components/navigation";
import { DeviceType } from "@onlyoffice/apps-ui-kit/enums";

const trail = [
  { id: "1", title: "Documents", isRootRoom: true },
  { id: "2", title: "2026", isRootRoom: false },
  { id: "3", title: "Contracts", isRootRoom: false },
];

export function Breadcrumbs() {
  const [current, setCurrent] = useState("Contracts");

  return (
    <Navigation
      title={current}
      navigationItems={trail}
      isRootFolder={false}
      currentDeviceType={DeviceType.desktop}
      isDesktop
      showTitle
      withLogo={false}
      burgerLogo=""
      titleIcon=""
      rootRoomTitle=""
      showRootFolderTitle={false}
      showNavigationButton={false}
      canCreate={false}
      getContextOptionsPlus={() => []}
      getContextOptionsFolder={() => []}
      onClickFolder={(id) =>
        setCurrent(trail.find((item) => item.id === id)?.title ?? current)
      }
      onBackToParentFolder={() => {}}
      isInfoPanelVisible={false}
      toggleInfoPanel={() => {}}
    />
  );
}
```

## Behaviour the types don't state

- **It renders up to four sibling elements.** The header and the right-hand button row are
  joined by a backdrop and the box while the drop box is open. Give it a header cell of its own.
- **`canCreate` alone shows no plus button, and the folder menu getter alone shows no folder
  button.** Each also needs `isPlusButtonVisible` or `isContextButtonVisible`, which have no default.
- **`getContextOptionsFolder()` is called on every render**, whether or not its button is rendered.
  `getContextOptionsPlus()` runs on every render of the plus button. Keep both cheap and free of
  side effects.
- `ref` reaches the header row, not the drop box.
- **The layout follows `currentDeviceType`, not the window.** On `desktop` the AI chat button and
  the info panel toggle sit in the right-hand row. Below it they join the button row, and the plus
  button is dropped.
- The warning chip is drawn only on `desktop`, and only when `titles.warningText` is set.
- On `tablet` the extra button moves to the end of the button row, after the tariff bar.
- **The AI chat button drops its label when the header is crowded.** It watches the row's width
  and keeps only the icon while anything else in the row is truncated.
- **The room title opens the second-to-last crumb.** With `rootRoomTitle` and a single crumb there
  is none, so a click only closes the drop box.
- **The drop box needs a `Section` for its height.** Without one the list takes the height of its
  own rows, however many there are.
- **`withLogo` and `burgerLogo` are image URLs**, not icon names. With `withLogo={true}` there is
  no desktop image, only `burgerLogo`.
- The whole component is memoised with `React.memo`, so a getter recreated on every parent render
  defeats it.

Set them on an ancestor of the component: it takes no `style` or `className`, and declares none
of them itself.

The folder name keeps the `Heading`'s own colour; `--navigation-title-color` reaches only the room
title. Between the phone and desktop breakpoints the heading is fixed at `21px`. So
`--navigation-heading-size` applies on desktop and phone only.

Some variables show only when a prop draws their element: the badge (`badgeLabel`), the pressed
toggle (`isInfoPanelVisible`) and the AI chat button (`toggleChatPanel`). The drop box's variables
show only while it is open. The header's other colours come from the theme and are not exposed.

## Accessibility

- **The trail is reachable by keyboard.** The folder name, the room title and the drop box rows have
  `role="button"`, take Tab focus and answer Enter and Space.
- **The folder name carries `aria-expanded`** while it can open the drop box. In the root folder or
  with an empty trail it is a plain heading.
- **Focus follows the drop box.** Opened from the folder name, it moves to the box's copy of that
  name. Closed with the focus inside, it returns to the header's folder name.
- **The logo is pointer-only.** It is a `<div>` with an `onClick`, and no role, `tabindex` or key
  handler.
- **The icon buttons are keyboard buttons.** The back arrow, the plus, the folder and the info
  panel buttons have `role="button"`, take Tab focus and answer Enter and Space.
- **Each is named.** The info panel toggle by `titles.infoPanel`, the plus by `titles.actions`, and
  the folder button by `titles.contextMenu`. Without them the plus is "Actions" and the folder
  button "More options"; the back arrow is always "Back", all translated.
- The AI chat button and the extra button are real `<button>`s, named by their visible label.
- The folder name and the room title are both `<h1>` elements, whatever the page around them. Each
  button sits inside its heading, so the heading keeps its role.
- The header is not a landmark: there is no `<nav>`, no `aria-label` and no breadcrumb semantics.
- The drop box is an ordinary positioned `<div>`, not a dialog. Escape closes it, and Tab can leave
  it.
- The logo's `alt` is the product name as the portal brands it; the burger image has an empty
  `alt`.
- **A passed `aria-*` lands on the header's container and is kept.** The container has no role,
  so a name there is not read.
