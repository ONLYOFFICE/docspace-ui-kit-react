# Table

Columnar list with resizable, sortable and hideable columns, laid out by a CSS grid the header
writes. Six components that only work together, and only one table to a page.

## Use this when / not when

- Use for data the user reads across and sorts: files, members, sessions, anything with columns
  worth resizing and hiding.
- Not for a list of items with one line each: use [`Rows`](../rows/README.md), or a flex column of
  your own.
- Not for a short, fixed table. This one saves column widths in `localStorage` and re-lays out
  its grid on every resize; a `<table>` of your own does not.
- Not twice on one page. The container's id, the header's id and the column ids are all
  literal.

## Import

```ts
import {
  TableBody,
  TableCell,
  TableContainer,
  TableHeader,
  TableRow,
} from "@onlyoffice/apps-ui-kit/components/table";
```

Also exported from the root barrel `@onlyoffice/apps-ui-kit`.

None of the props types are exported. `TTableColumn` and `TGroupMenuItem` are, and they are the
two you write by hand.

Needs `ThemeProvider` from `@onlyoffice/apps-ui-kit/providers/theme`, and
`TranslationProvider` from `@onlyoffice/apps-ui-kit/providers/translation` for the group menu's
own labels.

## Minimal example

The header needs the container's ref to write the grid on it, and a `columnStorageName` to save
the widths under.

```tsx
import { useRef } from "react";
import {
  TableBody,
  TableCell,
  TableContainer,
  TableHeader,
  type TTableColumn,
} from "@onlyoffice/apps-ui-kit/components/table";

const COLUMNS: TTableColumn[] = [
  { key: "name", title: "Name", enable: true, resizable: true },
  { key: "role", title: "Role", enable: true },
];

export function MemberTable({ members }: { members: string[] }) {
  const container = useRef<HTMLDivElement>(null);

  return (
    <TableContainer forwardedRef={container} useReactWindow={false}>
      <TableHeader
        containerRef={container}
        columns={COLUMNS}
        columnStorageName="membersTableColumns"
        columnInfoPanelStorageName="membersTableColumnsInfoPanel"
        sectionWidth={960}
        useReactWindow={false}
        showSettings={false}
      />
      <TableBody
        columnStorageName="membersTableColumns"
        columnInfoPanelStorageName="membersTableColumnsInfoPanel"
        filesLength={members.length}
        itemCount={members.length}
        itemHeight={41}
        hasMoreFiles={false}
        useReactWindow={false}
        fetchMoreFiles={() => Promise.resolve()}
      >
        {members.map((name) => (
          <TableCell key={name}>{name}</TableCell>
        ))}
      </TableBody>
    </TableContainer>
  );
}
```

## Recipes

### Sort the table by a column

A column sorts by calling back: the table does not reorder anything, and the arrow follows
`sortBy` and `sorted` on the header.

```tsx
import { useRef, useState } from "react";
import {
  TableContainer,
  TableHeader,
  type TTableColumn,
} from "@onlyoffice/apps-ui-kit/components/table";

export function SortableHeader() {
  const container = useRef<HTMLDivElement>(null);
  const [sortBy, setSortBy] = useState("name");
  const [descending, setDescending] = useState(false);

  const columns: TTableColumn[] = [
    {
      key: "name",
      title: "Name",
      enable: true,
      sortBy: "name",
      resizable: true,
      onClick: (field) => {
        setDescending(field === sortBy ? !descending : false);
        setSortBy(field);
      },
    },
    {
      key: "date",
      title: "Modified",
      enable: true,
      sortBy: "date",
      onClick: (field) => setSortBy(field),
    },
  ];

  return (
    <TableContainer forwardedRef={container} useReactWindow={false}>
      <TableHeader
        containerRef={container}
        columns={columns}
        sortBy={sortBy}
        sorted={descending}
        columnStorageName="filesTableColumns"
        columnInfoPanelStorageName="filesTableColumnsInfoPanel"
        sectionWidth={960}
        useReactWindow={false}
        showSettings
      />
    </TableContainer>
  );
}
```

### Select rows and act on the selection

The group menu takes the header's place while something is selected. Its select-all checkbox is
its own; the per-row checkbox is yours to put in a cell.

```tsx
import { useState } from "react";
import { Checkbox } from "@onlyoffice/apps-ui-kit/components/checkbox";
import {
  TableCell,
  TableGroupMenu,
  TableRow,
} from "@onlyoffice/apps-ui-kit/components/table";

export function SelectableRows({ names }: { names: string[] }) {
  const [selected, setSelected] = useState<string[]>([]);

  const toggle = (name: string) =>
    setSelected((current) =>
      current.includes(name)
        ? current.filter((item) => item !== name)
        : [...current, name],
    );

  return (
    <>
      {selected.length > 0 ? (
        <TableGroupMenu
          isChecked={selected.length === names.length}
          isIndeterminate={
            selected.length > 0 && selected.length < names.length
          }
          withoutInfoPanelToggler
          withComboBox={false}
          headerMenu={[
            {
              id: "delete",
              label: "Delete",
              title: "Delete",
              iconUrl: "",
              disabled: false,
              onClick: () => setSelected([]),
            },
          ]}
          onChange={(checked) => setSelected(checked ? names : [])}
        />
      ) : null}
      {names.map((name) => (
        <TableRow key={name} checked={selected.includes(name)}>
          <TableCell>
            <Checkbox
              isChecked={selected.includes(name)}
              onChange={() => toggle(name)}
            />
          </TableCell>
          <TableCell>{name}</TableCell>
        </TableRow>
      ))}
    </>
  );
}
```

## Behaviour the types don't state

- **The header lays out the whole table.** It computes a `grid-template-columns` string and
  writes it onto the container element and onto itself.
- The plain body and every `TableRow` are `display: contents`, so each cell is an item of the
  container's grid. Cells have no widths of their own, and a row outside that container is not
  laid out at all.
- **With `useReactWindow` the grid moves onto the rows.** The container and the body become
  full-height blocks. The virtual list wraps each row in a `.table-list-item` whose grid comes
  from the stored widths. As it resizes, the header rewrites every `.table-list-item` inside the
  container.
- **The header lays out on a desktop-wide window only.** Below 1024px, or without
  `columnInfoPanelStorageName`, it writes no widths on mount or on a resize.
- **The first layout.** A column with `defaultSize` gets that width, an `isShort` one its
  `minWidth`. The `default` column takes 40% of the rest, or all of it when no other column is
  enabled. The other enabled columns share the remaining 60% equally, never below 110px.
- With `withoutWideColumn` every column gets an equal share. Without it, the `default` column
  keeps at least its `minWidth`, or 210px without one.
- **Running out of room.** When the enabled columns do not fit at their minimum widths and a
  `default` column exists, the others collapse to `0px`. The `default` column takes the free
  width; `isShort` and `defaultSize` columns keep theirs.
- The header then greys the cog out, draws no resize handles and reports the change through
  `setHideColumns`.
- **`TableBody` renders an empty element unless both storage names are set.** A table missing
  the info-panel key shows nothing: no error, no rows. Pass both, always.
- **Column widths live in `localStorage`** under `columnStorageName`, or
  `columnInfoPanelStorageName` while `infoPanelVisible` is set. Two tables sharing a key
  overwrite each other's layout. A stored string whose column count does not match makes the
  header reset the widths.
- **The ids are literal.** The container is `#table-container`, the header
  `#table-container_caption-header`, and each header cell `#column_<index>`. The virtual list
  measures the first of those by id. One table to a page.
- **Only columns with an `onChange` appear in the settings menu**, and `isDisabled` keeps a
  column out of it. A column that must always show therefore cannot be unticked.
- Each settings entry is a checkbox labelled with the column's `title`, ticked while `enable` is
  set. Ticking it calls `onChange` with the column's key and changes nothing else.
- Flipping `enable` and storing the choice are the caller's job. The list stays open across ticks
  and closes on a click elsewhere or on the cog.
- **The sort arrow belongs to a column with an `onClick`.** It shows on hover, on keyboard focus,
  and while the column is sorted by or `active`. It is turned over while `sorted` is off.
- A click on the title calls `onClick` with the column's `sortBy`. A click on the arrow calls
  `onIconClick` instead, when the column has one. With `sortingVisible` off the arrow is gone and
  clicks do nothing.
- `isShort` narrows the space a header cell keeps for the resize handle from 22px to 12px, for
  a narrow column such as a row number.
- **`resizable` on a column describes the edge before it.** The handle is drawn at the end of the
  enabled column before it, and dragging it moves the boundary between the two.
- A drag stops at a column's `minWidth`, or 110px without one. The handle before a
  `defaultSize` column does not move at all.
- **`TableRow` draws the context button only while `contextOptions` has an item.** Otherwise a
  blank space takes its place.
- The button is a [`ContextMenuButton`](../context-menu-button/README.md) in `toggle` mode, so the
  row's own handler opens the menu, as a right-click does. The menu shows `contextOptions`, or
  the items `getContextModel` builds when it opens.
- **`checked` and `isActive` paint nothing on the row.** `checked` adds a `checked` class; the
  highlight itself is your styles.
- On a device with hover, children marked `create-share-link` stay hidden until the row is
  hovered, checked or active.
- While `dragging` is set, children marked `droppable-hover` are filled with the drop colour,
  unless the row is active or the rows are being reordered.
- **`hideColumns` on a row changes nothing on screen.** Nothing in the row reads it.
- **`isIndexEditingMode` is a reorder mode.** The header stops columns being resized and greys
  the cog out, and each row drops its context-menu cell altogether.
- **`TableCell` is a 48px box.** It has a bottom border, centres its content vertically and
  clips whatever does not fit.
- With `hasAccess`, a hover swaps a child marked `table-container_element` for one marked
  `table-container_row-checkbox`. With `checked` the checkbox stays shown either way.
- `TableCell` and `TableRow` are memoised with a deep comparison of their props, so updating
  one row does not redraw the others.
- **Virtualisation.** With `useReactWindow`, the body mounts only the rows near the view of the
  section's scroller, and three beyond it. The scroller is `#sectionScroll`, or the window.
- Each virtualised row is `itemHeight` tall. While `hasMoreFiles` is set, the body adds two
  placeholder rows and calls `fetchMoreFiles` as they come into view.
- Without `useReactWindow`, every row is rendered at once, which suits a short list only.
- On the body, `infoPanelVisible` only makes the virtualised rows read the info-panel key.
- `noSelect` on the container stops text selection anywhere in the table, for example while rows
  are being dragged. The container colours an element marked `indexing-separator`, to show where
  a dragged row will land.
- The line under the header and the group menu stops 20px short of each edge. `isLengthenHeader`
  draws it edge to edge, and so does a hover over the first virtualised row.
- The header watches the container with a `ResizeObserver` as well as the window, so it
  re-lays out when a panel opens beside it.
- `useReactWindow` defaults to `false` on the header and `true` on the body. Set it the same on
  all three parts, or the header lays out rows the body never renders.
- `TableCell` writes its `value` prop to the element as a non-standard `value` attribute, which
  drag and drop reads.
- The group menu needs translations of its own for the select-all checkbox and the selection
  combo box.
- **A `headerMenu` entry whose `disabled` is true renders nothing**, not a greyed button. An
  action that does not apply to the selection disappears from the toolbar.
- `isBlocked` is the greyed state: every button and its icon, clicks ignored, while an operation
  on the selection runs.
- The group menu lays its buttons out after a separator, in a scroller that runs sideways when
  they do not fit.
- Each button draws the icon fetched from `iconUrl` before its label, with `title` as the hover
  tooltip, or the label when `title` is empty. On a tablet the icon sits above the label; on a
  phone the label is not drawn.
- An entry with `withDropDown` calls its `onClick` and then opens its `options` in a menu under
  the button. The menu is 354px wide when its options carry descriptions; with
  `fixedDropdownStyles` it is 161px wide and five rows high at most.
- The group menu's info-panel button sits on a round background while `isInfoPanelVisible` is
  set. Its icon is mirrored in a right-to-left interface, and the `isCloseable` cross comes
  before it.

## CSS variables

The table styles itself from the theme; the column widths are written as inline
`grid-template-columns`. The group menu reads one variable, set on an ancestor of it.

| Variable                             | Default | Effect                                                                                                          |
| ------------------------------------ | ------- | --------------------------------------------------------------------------------------------------------------- |
| `--table-group-menu-checkbox-margin` | `28px`  | `margin-inline-start` of the select-all checkbox or `headerLabel`, on desktop only; below it the margin is 24px |

The `checkboxMargin` prop writes the same variable onto the toolbar itself, so when it is set it
wins over a value set on a wrapper.

## Accessibility

- Nothing here is a table to assistive technology. Every part is a `<div>`, with no `role`, no
  `columnheader`, no `aria-sort` and no row or column count.
- The title of a sortable column is a `role="button"` in the tab order, and Enter or Space sorts
  by it. The sort arrow beside it is left out of the tab order.
- Resizing has no keyboard route: the handles answer the mouse only.
- The settings cog is a focusable button that Enter or Space opens. It has no accessible name;
  `settingsTitle` is only its hover tooltip.
- Each row's context button is a focusable button, named by `title` or by the translated "More
  options" without one.
- Selection is whatever [`Checkbox`](../checkbox/README.md) you put in a cell, which is a real
  input.
- The group menu's action buttons are native `<button>`s rendered by
  [`Button`](../button/README.md), reached with Tab and pressed with Enter or Space. Each is named
  by its label, even on a phone where the label is not drawn.
- `isBlocked` sets the native `disabled` on the action buttons, which takes them out of the tab
  order.
- The group menu's close cross and info-panel button are focusable, but have no accessible name.
- The select-all checkbox has no visible label. Its only text is the translated "Select all", as
  a `title` on the label around it.
- **A passed `aria-*` lands on the outer element of each part and is kept.** No part has a role,
  so a name there is not read.
- Data a keyboard or screen-reader user has to work through is better served by a real
  `<table>` of your own, styled with the kit's `Text`.
