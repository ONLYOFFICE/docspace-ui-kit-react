# Button

Labelled action button with an optional icon, a loading state and a tooltip, in a primary or
secondary variant. It renders a real `<button>`, so form submission and keyboard activation
work natively.

## Use this when / not when

- Use when the user triggers an action in place: submitting a form, confirming a dialog,
  opening a panel.
- Not for an icon-only control in a fixed slot: use [`IconButton`](../icon-button/README.md),
  which keeps an accessible name without a visible label.
- Not for showing an operation already in progress: [`LoadingButton`](../loading-button/README.md)
  is a progress ring with a cancel cross, not this component's `isLoading`.
- Not for the "create new" entry at the top of the portal's main menu — that is
  [`MainButton`](../main-button/README.md).

## Import

```ts
import { Button, ButtonSize } from "@onlyoffice/apps-ui-kit/components/button";
```

Also exported from the root barrel `@onlyoffice/apps-ui-kit`.

Needs `ThemeProvider` from `@onlyoffice/apps-ui-kit/providers/theme` above it in the tree.
Without it the button renders in the light palette only, without the portal's accent colour.
The dark rules apply under a global `.dark` class that the provider sets.

## Minimal example

```tsx
import { useState } from "react";
import { Button, ButtonSize } from "@onlyoffice/apps-ui-kit/components/button";

export function SaveRow() {
  const [isSaving, setIsSaving] = useState(false);

  const save = async () => {
    setIsSaving(true);
    try {
      await fetch("/api/settings", { method: "POST" });
    } finally {
      setIsSaving(false);
    }
  };

  return (
    <div style={{ display: "flex", gap: 8 }}>
      <Button
        primary
        scale
        size={ButtonSize.normal}
        label="Save"
        isLoading={isSaving}
        onClick={save}
      />
      <Button scale size={ButtonSize.normal} label="Cancel" />
    </div>
  );
}
```

## Recipes

### Show a loading state while an action runs

`isLoading` is yours to drive around the await — the button does not track the promise.

```tsx
import { useState } from "react";
import { Button } from "@onlyoffice/apps-ui-kit/components/button";

export function DeleteButton({ onDelete }: { onDelete: () => Promise<void> }) {
  const [isDeleting, setIsDeleting] = useState(false);

  return (
    <Button
      primary
      label="Delete"
      isLoading={isDeleting}
      onClick={async () => {
        setIsDeleting(true);
        try {
          await onDelete();
        } finally {
          setIsDeleting(false);
        }
      }}
    />
  );
}
```

### Disable the button until a form is valid

```tsx
import { Button } from "@onlyoffice/apps-ui-kit/components/button";

export function SubmitButton({ isValid }: { isValid: boolean }) {
  return <Button primary label="Submit" isDisabled={!isValid} />;
}
```

### Add an icon to the button

`icon` takes a node, and the node is yours: the package does not publish its icon set, so
import the SVG through your own bundler. There is no `iconName` prop.

```tsx
import DownloadIcon from "./icons/download.svg?react";
import { Button } from "@onlyoffice/apps-ui-kit/components/button";

export function DownloadButton({ onDownload }: { onDownload: () => void }) {
  return (
    <Button label="Download" icon={<DownloadIcon />} onClick={onDownload} />
  );
}
```

### Lay out the buttons of a dialog footer

Primary first, then the secondary action; `scale` makes them share the width evenly.

```tsx
import { Button, ButtonSize } from "@onlyoffice/apps-ui-kit/components/button";

export function DialogFooter({
  onConfirm,
  onCancel,
}: {
  onConfirm: () => void;
  onCancel: () => void;
}) {
  return (
    <div style={{ display: "flex", gap: 8, width: "100%" }}>
      <Button
        primary
        scale
        size={ButtonSize.normal}
        label="Delete"
        onClick={onConfirm}
      />
      <Button
        scale
        size={ButtonSize.normal}
        label="Cancel"
        onClick={onCancel}
      />
    </div>
  );
}
```

### Make a destructive (red) button

There is no destructive variant. A delete confirmation is a `primary` button with
`--accent-button` set through its own `style`. Do not set the variable on the dialog or panel
around the button: that recolours everything accented inside, the close button included.

```tsx
import type { CSSProperties } from "react";
import { Button } from "@onlyoffice/apps-ui-kit/components/button";

// The primary variant reads it for its background and border.
const destructive = { "--accent-button": "#f21c0e" } as CSSProperties;

export function DeleteForeverButton({ onDelete }: { onDelete: () => void }) {
  return (
    <Button
      primary
      label="Delete forever"
      style={destructive}
      onClick={onDelete}
    />
  );
}
```

## Behaviour the types don't state

- **`type="reset"` does nothing.** Any `type` but `"submit"` renders `type="button"`, so a
  reset button never resets its form. Clear the fields from your own handler instead.
- **`aria-disabled` alone does not disable the button.** It stays focusable, and `onClick` still
  runs. Check the state in your handler, or use `isDisabled`, which blocks the click.
- **`isLoading` also disables the button.** The spinner covers the content, which stays in
  place, hidden. The button keeps its width, so the layout does not jump.
- **The label never wraps.** A label wider than the space the button gets ends in an
  ellipsis. `scale` does not help: it sizes the button to its container, not its text. Give
  the button room, or shorten the label.
- **There are two independent tooltips.** `tooltipText` is rendered by the button itself,
  below it and following the pointer. `title` and `tooltipContent` go to the `withTooltip`
  wrapper. Setting both kinds shows two tooltips, so pick one.
- **Buttons with the same `id` share a `tooltipText` tooltip.** The tooltip is named after
  `id`, so hovering one button opens the other's too. Without an `id`, each button gets a
  generated one.
- **The props type is closed.** `ButtonProps` does not extend `ButtonHTMLAttributes`, so
  `name`, `form` and `autoFocus` are TypeScript errors. At runtime the component still spreads
  unknown props onto the element.
- **The variants are not mutually exclusive in the type.** `primary`, `filled` and `accent`
  can all be passed together; the stylesheet decides, and `accent` — declared last — wins.
  Pass one.

## CSS variables

Set these on an ancestor to retheme the button. Everything else the stylesheet defines is
private to it.

| Variable                                        | Default                           | Effect                                                        |
| ----------------------------------------------- | --------------------------------- | ------------------------------------------------------------- |
| `--accent-button`                               | theme accent                      | Primary background and border, base hover border, accent text |
| `--accent-button-tint`                          | `--accent-button` at 10%          | Background of the `accent` variant                            |
| `--accent-button-tint-hover`                    | `--accent-button` at 18%          | Its hover background                                          |
| `--accent-button-tint-active`                   | `--accent-button` at 26%          | Its active background                                         |
| `--button-height-xs` / `-sm` / `-md` / `-lg`    | `24px` / `32px` / `40px` / `44px` | Height per `ButtonSize`                                       |
| `--button-font-size-xs` / `-sm` / `-md` / `-lg` | `12px` / `13px` / `14px` / `16px` | Font size per `ButtonSize`                                    |
| `--button-root-border-radius`                   | `3px`                             | Corner radius (the `accent` variant uses `6px` regardless)    |
| `--button-text-weight`                          | `600`                             | Label weight                                                  |
| `--button-focus-color`                          | accent                            | Colour of the keyboard focus ring                             |

Each state colour also has an override. The secondary variant reads the `--button-root-*` set,
the primary one the `--button-primary-*` set. The `filled` and `accent` variants read neither:
their colours are set on the button itself, out of a wrapper's reach.

| Variable                                                                   | Default | Effect                                                                                                             |
| -------------------------------------------------------------------------- | ------- | ------------------------------------------------------------------------------------------------------------------ |
| `--button-root-bg`, `--button-root-color`, `--button-root-border`          | theme   | Secondary background, text colour and border; the border is a `border` shorthand                                   |
| `--button-root-bg-hover`, `-color-hover`, `-border-hover`                  | theme   | The same three on hover and under `isHovered`                                                                      |
| `--button-root-bg-active`, `-color-active`, `-border-active`               | theme   | The same three while pressed; background and text colour also under `isClicked`                                    |
| `--button-root-bg-disabled`, `-color-disabled`, `-border-disabled`         | theme   | The same three while disabled or loading; under `isDisabled` the border is drawn in the text colour                |
| `--button-primary-bg`, `--button-primary-color`, `--button-primary-border` | theme   | Primary background, text colour and border; the border is a `border` shorthand and is kept on hover                |
| `--button-primary-bg-hover`, `-color-hover`                                | theme   | Primary background and text colour on hover and under `isHovered`                                                  |
| `--button-primary-bg-active`, `-color-active`, `-border-active`            | theme   | Primary background and text colour while pressed and under `isClicked`; the border takes a colour, not a shorthand |
| `--button-primary-bg-disabled`, `-color-disabled`, `-border-disabled`      | theme   | The same three while disabled or loading                                                                           |

**There is no destructive variant.** Override `--accent-button` on the button itself, as in
[Make a destructive (red) button](#make-a-destructive-red-button).

Use a wrapper element only when one variable has to cover several buttons. Avoid it inside a
row that shares its width: a wrapped `scale` button stops being an equal flex item and shrinks
to its label.

## Accessibility

- Renders a native `<button>`, so Enter and Space activate it and it takes part in tab order
  without help.
- **A passed `aria-*` is kept**, and a passed `aria-label` wins over `label`. `isDisabled` and
  `isLoading` set `aria-disabled` and `aria-busy` to `true` over a passed value.
- **An icon-only button needs an `aria-label`.** Without `label` or `aria-label` it has no
  accessible name.
- **Only the keyboard gets a focus ring.** A click leaves no outline. Keyboard focus draws a
  2px accent ring 2px clear of the button, so it shows on the primary variant too.
  `--button-focus-color` overrides its colour.
